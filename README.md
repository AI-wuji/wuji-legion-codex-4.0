# 无极军团 5.0 · 阿极直带专家的任务优先工作体系

> 让人只需要说清楚目标，由阿极选择最小正确路径，把真实任务安全地做完。

无极军团不是另一个 Codex，也不是要求用户记忆 Skill、插件、MCP 或模型名称的软件平台。它是运行在现有 AI 宿主之上的**任务优先工作体系**：阿极负责统一沟通和判断，按任务组合必要能力，调用现有工具完成真实交付，并把证据、失败和经验留在可追溯边界内。

仓库可以保留4.0及更早代码和资料作只读历史追溯，但项目与已装备Codex的运行入口只允许5.0；旧版角色链、路由、CLI命令和协作流程均已封锁，不作为兼容执行通路。5.0由阿极在当前会话按需直办或直接调用必要专家分身。

动效制作已新增按功能命名的 **动效制作专家**，接入可编辑代码动画、画面评论修改和有声导出；本机有界验收、调用入口及限制见 [动效制作专家](docs/motion-graphics-expert.md)。

## 初衷

### 对外

很多人知道自己想要什么，却不应该先学习一套复杂的 AI 操作语言。用户可以直接说：

- “帮我分析这批资料，给出有依据的结论。”
- “把这个需求实现出来，并告诉我怎么验证。”
- “把这些内容整理成可以交付的文档或演示。”
- “这个方案可能有问题，请指出风险并给出更稳妥的路径。”

用户不需要先指定专家、Skill、插件或 MCP。阿极会先判断任务，再按需引用现有能力；简单请求直接完成，专业任务可直办或调用单个专家，只有存在独立分支时才拆分并发。

### 对内

无极军团5.0延续4.0的任务优先原则，并将协作入口简化为阿极直接调用专家。它不是“再造一个更大的模型平台”，而是把真实工作中的几个问题收敛到一条可复用的最小路径：

1. 任务目标、权限、输入、输出和验收边界必须明确。
2. 专业能力应按需组合，而不是把所有规则和上下文一次性塞进每个请求。
3. 失败、未知和外部阻断必须如实保留，不能用目录、提示词或 mock 冒充完成。
4. 新技术和经验必须先有来源、范围、反例和证据，不能因为一次成功就自动晋升为全局真理。
5. 能复用现有宿主、Skill、MCP、CLI、API 或专业项目时，不重复造轮子，也不强迫所有项目改写成同一种语言。

## 它是什么

无极军团由三层组成：

1. **阿极入口**：唯一面向用户的沟通与交付入口，负责理解目标、必要拆分、专家选择、并发和整合；简单任务直接完成。
2. **按需能力组合**：专家与工作流按MoE方式冷态保存，仅为当前任务启用必要分身和Skill/MCP/工具，不预先启动全体专家。
3. **兼容辅助**：复用宿主原生代理、Skills、MCP、CLI/API；仓库小工具保留契约与诊断用途，不替代模型宿主或扩建通用调度平台。


```mermaid
flowchart LR
  A[用户目标] --> B[阿极：理解、质疑、定界、统一交付]
  B --> C[最小正确能力组合]
  C --> D[现有 Skill / MCP / CLI / API / 专业项目]
  D --> E[隔离执行]
  E --> F[独立检查与可回读证据]
  F --> G[用户交付]
```

## 核心优势

### 原子化组合，而不是专家堆叠

无极军团把可复用能力拆成有边界的原子：输入、输出、权限、依赖、适用范围和证据要求都要明确。原子可以组合成能力包，再由任务配方组装成一次工作流。

- 同一个原子可以被多个领域复用，不必复制成几十个同名专家。
- 专业差异留在专业原子和适配器中，不被统一模板抹平。
- 失败可以定位到具体原子、工具、输入或验收环节。
- 没有真实任务消费者时，只保留设计和索引，不预建大量无用应用。

### 最小上下文，按需读取

简单问答和普通改写不启动军团大会；专业任务只读取必要指引和原文。上下文、工具输出、完整证据、压缩策略和模型规格分别记账，不能用一个数字冒充全部限制。

### 白帽判断和证据优先

阿极不以迎合用户为目标。前提错误、证据不足、权限不够、方案有风险或外部能力不可用时，应明确指出并给出可行路径。成功必须绑定真实产物、当前版本、独立检查和可回读证据；失败也要保留真实失败原因。

### 兼容现有生态

核心只使用必要的 Rust/SQLite 小辅助；Python、TypeScript、Go、C++ 以及各专业软件保持原生态。当前5.0入口优先复用Codex会话原生子代理；既有Skill、MCP、CLI、API和专业工程作为能力来源或辅助诊断，不为了架构统一而强制重写。

### 受控进化，不自动污染全局

技术资料和真实经验沿同一条进化链管理：来源、许可、范围、反例、复核、版本和失效条件必须分开记录。一次用户偏好、一次成功或一个漂亮模板，都不能自动升级为公共规则、全局知识或永久能力。

### 隔离、可撤销、可回溯

任务使用独立工作区、明确写集和权限边界。源文件、版本、scope、hash、release 和回执保持绑定；任务取消、来源变化、输出变化或验证失效时，旧完成状态不能被悄悄复活。

### 无极军团5.0：阿极直接带专家

阿极作为轻量入口，按需调用专家分身并负责拆解、依赖判断、并发调度和统一交付：

`用户目标 → 阿极 → 必要专家分身（独立分支尽早并发）→ 阿极整合交付`

- 参谋部和主帅不是必经代理层；其拆解/协调职责由阿极承担，主帅经验沉淀为可检索、按需加载的工作流配方。
- 专家、工作流与方法角色均为MoE冷态资源，只启用当前任务所需分身；完成后释放，未用角色不进入上下文。
- 独立且已就绪的分支尽早并发；仅真实依赖、写入冲突、权限或资源限制才串行。用户插话先答复，再继续原任务，除非明确取消或替换。
- 只传递必要任务、资料、产物与状态，不要求冗长思考过程；检查只在用户要求或存在具体重要风险时执行。
- Codex当前会话原生子代理是默认执行桥；项目内CLI/app-server仅作辅助/诊断，不冒充当前会话代理执行。
## 使用方式

本项目源默认采用5.0直接专家通路。全局 Codex 是否已安装并加载5.0，以用户级 AGENTS/Skill 目标文件和新会话观察为准，不能由仓库内容推断。普通使用无需运行CLI或输入激活语，直接告诉阿极目标即可；阿极按需直办或启用必要专家分身，并让独立分支尽早并发。4.0及更早资料仅作只读历史；所有旧版执行路由均禁用。本仓库CLI/app-server桥仅为辅助/诊断，不冒充当前会话原生委派。

复杂任务遵循以下原则：

1. 先确定目标、输入、交付物和禁止动作。
2. 优先复用现有能力，只加载当前任务需要的部分。
3. 真实执行后独立检查产物、来源、权限和当前 hash。
4. 交付结果、证据、失败和未知，不把计划或目录当成执行结果。

项目内 `tools/wuji4.py` 和 `tools/run_legion_task.py` 是开发期的有界诊断/辅助工具，不是5.0激活步骤、默认任务入口或原生专家委派替代品；日常使用直接向阿极描述目标即可。

## 模型基准与按需升级

- 用户在当前项目对话中最后明确选定的 `model + effort` 保存为“默认基线”；普通任务始终沿用该基线，不强制 Sol medium、不降到 DeepSeek、不建备用链。用户明确换模型或 effort 时，才更新默认基线。
- 难题处理只做临时升档：按需要请求 `gpt-6.1-sol high`，特别复杂或反复定位无进展时请求 `xhigh`，不要求默认基线先失败；当前已是 Sol high/xhigh 且满足所需档位时不重复切换，也不把 xhigh 降为 high。难题完成后，普通任务必须恢复到进入难题前保存的默认基线；临时升档不修改默认基线。
- 升级和回基准只通过现有宿主原生显式调用/委派能力执行；主对话不能切换时说明边界，不以文字要求、改配置或委派冒充主对话已切换。
- `requested`（请求）、`configured`（登记配置）、`observed`（实际观察）、`effective`（可信证据确认的生效值）分开；不可核验的值为 `unknown`。失败不盲重试、不串备用 provider、不默认付费。
- 保留可见历史、工具真实回执、产物路径/hash 和副作用状态；不覆盖失败或把未知提交当未提交。本规则不证明自动换模已实现或已实测，也不改变其他安全、权限和专业验收边界。

本次行为规则及原生执行边界见 `docs/design-deltas/028-current-selection-baseline-and-upgrade-only-2026-10-08.md`；不是自动换模实测结论。

## 边界与安全

- 不把无极军团说成另一个 Codex、通用模型宿主或全能专家平台。
- 不预建 92 个应用、适配器或常驻专家来凑验收数量。
- 不修改用户的模型、provider、凭据、插件、音频设备或其他全局配置来制造通过。
- 不付费、不外发私有资料、不发布未经授权的内容、不清理用户文件。
- 不以本地 mock、目录、提示词或历史回执冒充真实宿主、原生模型或专业效果。
- 4.0及更早实现仅作只读历史留档，当前运行入口不允许调用；不以本地mock、目录、提示词或历史回执冒充真实宿主执行和专业效果。
