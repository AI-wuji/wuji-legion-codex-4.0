# 无极军团5.0复查与收敛记录

日期：2026-10-30（Asia/Shanghai）

范围：当前项目 `wuji-legion-codex-4.0` 的5.0活动入口、目录、辅助执行器、文档、测试，以及父目录 `wuji-legion-codex-3.0` 的静态架构和演进资料。3.0/4.0内容只用于历史对照，没有作为本次运行入口加载或执行。

## 结论

5.0的核心方向已经成立：阿极是唯一用户入口，简单任务直办，专家按需冷态启用，独立分支尽早并发，旧版链路被运行时拒绝。当前主要问题不是再增加角色或调度器，而是把“5.0活动契约”和“4.0历史实现”彻底分层，并把3.0最重要的能力演进原则落到当前目录的可验证边界上。

本次已完成以下收敛：

- 新增 `catalog/p3/direct-expert-manifest.json`，明确 `expert -> aji` 回交、无 staff/leader 必经层、冷态角色、未知提交不盲重试和独立验证边界。
- `legion/task-entry-5.0.json` 现在显式登记5.0直接专家目录和58项冷态角色目录。
- 5.0辅助执行器在加载角色目录时校验直接专家 manifest，防止旧4.0回交链被目录漂移重新接回。
- 4.0 `delegation-manifest.json` 标记为 `legacy_read_only_4_0`、不可作为运行入口，并指向新的5.0目录。
- README、5.0迁移表和当前边界表改用5.0直接专家契约；4.0配方保留为历史只读材料。
- 新增入口漂移回归，验证5.0直接回交和4.0目录排除关系。

## 从3.0继承且必须保留的初心

3.0资料中最有价值的不是“参谋部/主帅”层级，而是以下原则：

1. 阿极保持唯一用户交流、白帽判断和最终交付入口。
2. PonyTail要求选择最短正确路径，不为显示专业而增加角色、计划或仪式。
3. 角色和Skill必须冷态按需加载；目录存在不等于能力已调用。
4. 来源、版本、原子、融合物种、发布版本和真实调用入口要形成谱系；不可调用的资产不能冒充融合成果。
5. 真实产物、当前hash、宿主回执和独立验证才可以支撑完成；fixture、准备契约和提示词只能证明准备或形状。
6. 来源更新应做差异和影响分析，不覆盖旧代，不把一次成功自动升级成全局规则。

5.0正确地删除了3.0中不再必要的固定参谋部和主帅跳转，但目前仍需把上述谱系和可调用性规则从历史设计字段落实为活动目录的检查项。

## 发现的问题

### 已修复

- 5.0文档称直接专家通路，但 `delegation-manifest.json` 仍是4.0的 `bounded_staff_delegation_manifest`，并声明 `expert_to_leader_to_staff_to_aji`。虽然旧 `delegate` 已拒绝执行，目录和文档仍会造成错误发现。
- `run_legion_task.py` 的5.0角色加载只校验 `experts.json`，没有校验当前活动目录是否仍然是直接专家契约。现在增加了直接 manifest 和角色数量的一致性检查。
- README和迁移表仍把4.0委派目录称为专家委派配方；现在区分5.0直接目录和4.0历史目录。

### 仍需改进

- `catalog/p3/experts.json` 的 `baseline`、`design_source` 和大量 `source_evidence` 仍以4.0设计文件为来源。这可以作为谱系事实，但不应继续被描述为5.0运行基线。下一步应增加独立的5.0 catalog release 元数据，记录采用的5.0规则、来源差异、许可证和当前可调用状态。
- 5.0专家选择仍主要依赖阿极读取索引和构造任务，项目内没有一个完整的机器可校验“触发、反触发、输入、输出、权限、验收、回交”目录。直接 manifest目前只校验总契约，不能替代每个专家的专业准入。
- `tools/run_legion_task.py` 仍包含大段已封锁的4.0选择、staff、leader和aggregate实现。它们不会由5.0公共命令执行，但会增加误读和维护成本。适合下一轮拆到明确的 `legacy/4.0` 只读工具区，或从活动辅助模块移除；本次保留以避免改变历史测试和回溯路径。
- `tools/wuji4.py`、`legion/task-entry.json`、`legion/skills/wuji-legion-4-0`以及4.0测试仍位于项目可见路径。它们应继续保留作历史证据，但活动文档和默认测试入口不应再把它们当作当前功能。
- 当前5.0没有宿主层真实暂停/恢复、原生专家退出、有效模型/档位/配额的项目内证明。相关字段必须继续保持 `unknown`、`not_claimed` 或“契约已准备”，不能升级为能力完成。

### 应剔除或降级的内容

- 从5.0活动导航中剔除4.0委派目录、4.0 staff/leader回交链和4.0默认快速开始；保留文件，但明确只读历史。
- 不再为5.0恢复固定主帅、参谋部、全专家兜底或常驻调度器。
- 不再把58项冷态角色数量、27条旧配方或任何目录规模当作能力覆盖率。
- 不再把CLI/app-server辅助桥称为当前Codex原生专家执行；只有当前会话真实宿主回执才可证明原生执行。

## 优先级

1. **P0：活动入口纯化**。把 `tools/run_legion_task.py` 中已封锁的4.0代码移入只读legacy模块，更新4.0测试的发现范围，保留5.0直接专家测试。
2. **P1：5.0目录发布契约**。为专家目录增加5.0 release、来源差异、许可、失效条件、可调用入口和独立验证要求；每次目录变更重新生成hash和影响清单。
3. **P1：直接专家选择检查**。为角色选择增加反触发、必需输入、写集、依赖、回交字段和最低验收的确定性检查；匹配不到时返回 selection gap，不静默兜底。
4. **P2：宿主证据闭环**。只有在真实任务消费者出现时，补宿主原生spawn、回执、关闭、unknown查询和跨上下文恢复的有界验收。
5. **P2：历史文档分层**。将4.0执行账、旧安装记录和旧测试结果统一加历史标签，避免未来把历史日期或局部通过误读为5.0当前能力。
