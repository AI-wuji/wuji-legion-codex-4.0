## 已复现并修复

| 缺陷 | 根因与最小修复 | 回归覆盖 |
|---|---|---|
| 执行日志路径校验不完整 | 只检查字符串，不能拒绝Windows路径别名或链接元数据。`evaluate`复用现有`confined_path`，不另造路径校验器。 | 点路径、重复分隔符、尾部点/空格及reparse元数据拒绝；链接标记拒绝前不读内容。reparse负例采用受控元数据模拟，不冒充新建真实symlink。 |
| 哈希与解析可能读取不同内容 | 日志、当前核心回执和crosswalk回执的哈希与解析采用独立读取；改为同一字节快照，日志保留Windows换行兼容。 | 受控二次读取/读取后改写可复现原先哈希与解析脱节，修复后身份哈希绑定实际解析快照。不是对恶意并发改写的全工作区原子性保证。 |
| Rust日志冲突被最后一条覆盖 | 同一案例先失败后通过的记录被字典覆盖；现在与Python日志一样拒绝矛盾重复结果。 | 矛盾Rust案例不能生成通过数；相同结果的重复仍兼容既有日志。 |
| 损坏回执可崩溃或含糊通过 | 宽松JSON允许重复键和NaN，错误类型触发异常；当前投影复用严格JSON、检查必要section，损坏/不可读回执保持未完成。 | 截断JSON、非对象、重复键、非有限数、错误section类型及不可读配置；不自动修复用户配置。 |
| 资源记录scope漂移仍允许转移 | begin-transfer缺少记录级scope复核；复用既有`require_record_scope`，覆盖新意图和重放。 | 新转移、待接收与已完成重放均拒绝错scope；合法恢复后仍可幂等重放。 |
| 损坏转移意图仍可重放成功 | 历史意图只查JSON引用，未核哈希和授权绑定；复用既有`checked_payload_grant`并核意图身份。 | 载荷hash、scope、内容和身份变动拒绝；保持单一意图，不产生重复写事实。 |
| 嵌入包清单混淆JSON类型 | Python字典相等把1/true、0/false、整数/浮点视为相等；比较排序键后的JSON，保留类型差异。 | 三种类型替换拒绝；对象键顺序变化仍通过。 |

T22当前语义证据增加两个转移负例为必需案例，防止仅凭旧案例集晋升当前通过。另将开发期包收口检查的固定用例数改为实际已加载测试数，避免后续正常增加测试被错误判为失败。
