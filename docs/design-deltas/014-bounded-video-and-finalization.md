# 独立短视频链与收尾证据纠偏

## 具体任务阻塞与最小改动

已有 PNG 的编码任务不需要 ComfyUI。本机当前 ComfyUI 端口拒绝连接；不通过启动服务、安装或改现用环境解除它。独立 `run-video` 调用已固定的现有 FFmpeg，仅完成一秒八帧无音频 MP4，并由另一进程实际解码，保留当前输入、输出、工具和配置 hash。它不是 `run-media` 的自动 fallback，不创建调度器、常驻服务或第二份状态数据库。

源依据复用同一来源账 `docs/source-decisions.md`：官方 image2 文档已提供 `pattern_type=none`，直接采用而非猜测文件名规则。真实任务与失败边界仍由本次产物回归核验，不把公开文档算成本机执行。

## 实际修复

- OfficeCLI 失败回执使用 `state` 而非 `status`，框架曾错误退出零；成功现在绑定明确完成字段，失败保留 JSON 并退出非零。
- 回归过程中重写日志时检查旧发布包的当前源码闭包，产生封包/回归循环。回归只核既有治理来源、日志及上一归档身份；本次完整闭包仍由封包后的总审计严格核验，不删正式包一致性检查。
- T24/T85 的 hash 和报告断言不足以证明完整场景，已纠正为 supporting/partial。来源许可/在途治理以及当前接口 schema/实际派发漂移拒绝仍缺，不为进度数字放宽验收。
- 专业输入、工作区与回执在 resolve 前拒绝符号链接身份；媒体回执不可写到外部，输出采用独占创建或 FFmpeg `-n`，不覆盖历史文件。
- FFmpeg 二进制固定 SHA256，子进程移除 `FFREPORT`，限制 `file,pipe` 协议，显式关闭 image2 文件名模式；超过回应预算的完整标准输出/错误保留为有 hash 的文件并判失败，不悄悄截掉证据。
- 配置缺失、不可读或前后变化都不能成功；模拟失败回归不改真实配置。

## 证据与闭环顺序

当前真实独立视频证据为 `outputs/p4/video-framework-workflow-evidence.json` 和 `outputs/p4/video-framework-output.mp4`。ComfyUI 当前失败与此前成功探针分别保留，能力视图不把历史 available 当当前服务健康。

所有源码、指引和来源账修改完再统一回归；顺序为真实回归 → 验收账 → crosswalk → 持续报告 → 本地封包 → 包外总审计 → 包校验。封包后不再重写包内回归日志来破坏闭包。完整通过数来自正式执行账，不能由测试数量推导。

此增量只扩展有界任务和修复具体缺陷，不证明专业剪辑、音画效果、Word/Excel 全链、自动学习或全部 95 项验收。P7、全局挂载、现用 Codex 配置及关机均不执行。
