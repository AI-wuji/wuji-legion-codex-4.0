# Budget Semantics and GPT-6.1-Sol Context Correction (2026-10-05)

## 变更目的

修正活动 v1.7 中预算、上下文、压缩和输出上限的语义，避免把历史模型配置值或宿主策略值误报为 `gpt-6.1-sol` 的完整上下文，也避免把工具摘要预算误报为任务或计费上限。

## 当前规则

| 数值/字段 | 正确含义 | 不能推出的结论 |
| --- | --- | --- |
| `4096` | 单项工具/函数返回在对话历史中的有界摘要预算；完整证据和制品仍通过引用、文件和 hash 回读 | 不是完整证据大小、任务总 token、模型上下文或计费上限 |
| `240000` | 用户侧登记的自动历史压缩策略阈值 | 不是模型完整上下文、任务总 token、输出上限或计费硬限 |
| `90000` | 项目侧登记的 Skill 投影/注入预算 | 不是模型完整上下文、全项目可用 token、输出上限或计费硬限 |
| `272000` | 当一次请求的输入超过该值时，官方定价对该次完整请求提高输入/缓存与输出价格；另保留为历史/其他模型配置值，不再绑定到 `gpt-6.1-sol` 的上下文 | 不是 `gpt-6.1-sol` 的完整上下文窗口，也不是该模型的最大单次调用 token 上限 |
| `1050000` | 官方 `gpt-6.1-sol` 模型规格中的上下文窗口 | 不能证明当前 Codex 宿主已经向本会话开放或有效暴露全部窗口 |
| `128000` | 官方 `gpt-6.1-sol` 模型规格中的最大输出 token 数 | 不能证明当前宿主会话、自动压缩策略或工具调用实际允许该值 |

官方依据（页面当前显示值，2026-10-05抓取）：

- OpenAI 模型页：`https://developers.openai.com/api/docs/models/gpt-6.1-sol`

该模型页同时说明：超过 `272K` 输入 tokens 时，整次请求按更高的输入/缓存和输出费率计价。模型页的上下文窗口与最大输出字段是模型规格；当前 Codex 宿主是否实际暴露这些值仍需单独的可信宿主观察。

## 记录与执行影响

1. 继续分别记录 `configured`、`observed`、`effective` 和 `unknown`；没有当前宿主的可信遥测时，不把官方规格或登记文件改写成有效观察。
2. 不因本次数字修正修改 `config.toml`、模型/provider/reasoning、凭据、插件、全局 Skill 或音频设备。
3. 不把 `240000`、`90000` 或 `4096` 用作压缩证据、删减完整回执、承诺费用或限制专业任务的理由；证据超出摘要预算时返回引用和回读句柄，而不是静默截断。
4. 不以 `1050000` 推导当前宿主可安全装入的目录预算；此前由未知窗口推导的 `5440` 保持禁止。
5. v1.6 原稿中的历史数字只读保留；本修订只覆盖活动 v1.7 的解释、T70/T71 映射和当前报告语义。

## 验收边界

- 本修订解决的是数字语义和错误推断风险，不伪造当前 Codex 宿主的有效上下文、压缩行为、额度、费用或输出观察。
- 不新增 MCP、专业应用、模型调用或 95 项场景的预建验证；真实任务需要时再按任务范围检查。
- T70/T71 的通过条件仍要求证据层级分离；局部单元测试不能替代当前宿主或专业任务的原生观察。
