# 028：当前选择为基准，只按难题需要升级

日期：2026-10-08。用户明确授权将默认模型策略改为“当前选择为基准、只按难题需要升级”，并同步到项目内容与本机入口。

## 行为规则

- 用户在当前项目对话选定的 `model + effort` 是基准；普通任务继承，不强制 Sol medium、不降到 DeepSeek、不建备用链。用户中途明确换模型或 effort 时，以新选择更新基准。
- 难题可按需要直接请求 `gpt-6.1-sol high`，特别复杂或反复定位无进展时请求 `xhigh`，不要求基准先失败。当前已是 Sol high/xhigh 且满足所需档位时不重复切换，不把 xhigh 降为 high；难题结束后普通任务回原基准（若用户已更新，则回新基准）。
- 升级和回基准只通过现有宿主原生显式调用/委派能力执行；主对话不能切换时说明边界，不以文字要求、改配置或委派冒充主对话已切换。
- `requested`（请求）、`configured`（登记配置）、`observed`（实际观察）、`effective`（可信证据确认的生效值）分开；不可核验的值为 `unknown`。失败不盲重试、不串备用 provider、不默认付费。
- 保留可见历史、工具真实回执、产物路径/hash 和副作用状态；不覆盖失败或把未知提交当未提交。本规则不证明自动换模已实现或已实测，也不改变其他安全、权限和专业验收边界。

默认基线是进入普通工作时最后一次由用户明确选择并保存的 `model + effort`；不从模型自报、配置文件或委派请求推断当前主对话已生效。进入难题前保存该基线，难题只临时升到 Sol high/xhigh；难题完成后普通任务恢复已保存基线，临时升档不改基线。基准不可见时保留unknown，不用Sol medium或其他固定值补齐。仅模型或仅effort被明确更新时，更新对应项，另一项沿用已有基准。

## 原生执行和证据边界

- 原生接口能显式指定model/effort且授权、费用和额度条件成立时，才执行对应调用/委派；没有该能力就回交具体边界，不另造换模宿主、不改全局配置或模型通道。
- 委派的请求、真实工具回执与实际观察只证明该次委派；不证明主对话切换。主对话不能切换时明确说明，普通任务仍按用户基准处理；需要恢复主对话选择而无能力时提示必要用户动作，不声称已经恢复。
- 失败、429、未知提交或副作用未确认时保留原回执与状态；不盲重试、不串备用provider、不默认付费。受既有授权和预算约束、有新证据且明确未提交或可核验幂等的定点重试，仍按原安全规则处理。
- 可见历史、工具真实回执、输入/产物路径与hash、副作用状态沿现有机制保留；不静默覆盖、删减或把后来成功倒填为此前成功。本次不新增证据服务或虚构模型遥测。
