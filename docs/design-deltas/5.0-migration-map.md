## 5.0全角色MoE激活策略

- 阿极保持轻量协调入口；参谋/主帅不作必经代理，相关配方作为工作流知识。专家/方法角色MoE冷态，只有必要实例才启动。
- 具体任务选择的分身进入active，仅加载该任务所需角色职责和能力引用；无关角色不进入上下文、不调用模型、不占并发槽。完成/取消后关闭并释放；待依赖时只保存最小检查点，宿主不支持暂停则关闭后通过原生恢复机制续接。
- 这是外层角色路由/生命周期规则，不是对底层模型MoE架构的断言，也不保证任何宿主具备真实暂停能力。

## 5.0直派执行增量

- `tools/legion_pipeline.py`新增`execute_direct_experts(work_item, tasks, invoke_role, ...)`：阿极预选专家后直派执行，复用既有依赖、写集冲突、并发槽、产物范围/hash与回执约束；不调用主帅plan/aggregate，结果由阿极合并。
- `tools/run_legion_task.py`新增显式入口`execute_aji_direct_experts`：校验专家ID确实存在于冷态目录，再调用直派执行器。旧`delegate`和`execute_delegation`被封锁，历史实现不允许由当前CLI调用，5.0以Codex会话原生委派为首选。
- 现有CLI/app-server桥仅作辅助/诊断，尚未接通等价当前会话原生委派。本次同步没有发起真实专家模型调用；fixture只证明契约代码行为。
- 定向测试覆盖：不调用staff/leader、同专家多分身并发、真实依赖串行、unknown不重发但继续独立分支、未知专家ID拒绝调用。
- 网页/搜索结果不是本地文件回执；该执行函数不制造搜索能力。搜索工具由当前host任务桥提供，未提供时明确降级。



## 上下文连续性与压缩恢复

- 新增`legion/skills/wuji-legion-5-0/references/context-continuity.md`，并通过5.0入口和`task-entry-5.0.json`引用。
- 方法来源复用既有`docs/external-capability-adoption-2026-10-13.md`：ECC的选择性状态/记忆沉淀、Context Mode的代码侧大输出聚合、仓颉式资料蒸馏；落为最小恢复包，不搬用外部runtime、hooks或第二状态库。
- 恢复包只用于长任务、跨上下文/角色交接、多分支、重要副作用或压缩前；记录目标/权限、已做与回执/产物/hash、未完成分支/依赖/下一步、阻塞/unknown、来源引用及活动角色状态。短任务可直接从上下文续做，不新建状态文件。

## 全领域PonyTail与任务图谱增量

- PonyTail作为跨领域行为理念写入项目和用户级执行基线，适用于问答、研究、写作、规划、创作、办公、图谱与工程；不等同于也不依赖某个开发Skill。
- 新增最小正确路径、错误自主修复/依授权安装、快答与结果优先输出、专家间结果化交接等硬规则；无法自行排除的真实阻塞之外，继续完成独立分支。
- 验收采用按需策略：不对每一步例行检查或重复验收，只在用户要求、具体风险、关键结果影响下一步或交付确有必要时执行最低成本检查，达到目的即停。
- 恢复复杂任务的轻量任务图谱作为依赖与上下文控制工具：简单任务不建图；多分支/长任务/交接任务以最小DAG投影节点所需上下文。历史图谱理念复用，不恢复旧角色层级或宣称完整typed store已投产。
