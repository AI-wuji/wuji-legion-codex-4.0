## 3. 课程统一框架与契约模板

### 3.1 五要素是共同主体

专家、负责人、阿极、女娲、审查角色都按角色、任务、流程、约束、输出编写。程序组件使用同样的职责表达，但不假装成思考模型。

| 课程要素 | 契约字段 | 工程补充 |
|---|---|---|
| 角色 | role/specialty/boundaries | 我负责/我不负责、唯一产物 owner |
| 任务 | mission/triggers/anti_triggers | 目标、非目标、适用场景 |
| 流程 | workflow/handoffs | 依赖、阶段门、串并行、失败回交 |
| 约束 | constraints/permissions | PonyTail、白帽、来源、预算 |
| 输出 | outputs/acceptance | schema、验证、位置、交付形态 |

统一增加 ID、版本、来源定位、输入、工具、经验范围、任务图模板、回滚条件。字段齐全不等于专业质量。

### 3.3 团队、工具、模板的同框架写法

负责人须写任务范围、交付责任、条件成员引用、阶段 DAG、输入输出、工具、授权、验收和定向返工。执行课程“复用已有专家”：团队引用池中 ID，不生成副本。专业产物由对应专家/执行节点承担；轻量任务可同一节点兼任，但如实记录，不假装多人已运行。

工具用用途/边界/输入/步骤/限制/结果验证映射五要素。模板分固定结构与变量槽，采用“满意输出固化”方法。方法模板不具有执行权限。

### 3.4 模板质量门

每个专家须有正触发、反触发、正常、缺料、失败回交样例。每个负责人须有依赖及合理并行条件。不能只写“专业、高质量、擅长”。漫剧专属规则只在相应方法包启用。没读到的材料不得声称已依据其编写。

正式角色的五要素字段逐项关联课程原文页/章节，专业delta关联WorkBuddy原始成员、其它方法/脚本/资产及当前版本；共用原子经字段出处索引承接，不能因共享而失去阅读证明。课程直接给出的适配模板优先；未覆盖专业依其书写规则并引用领域真实材料独立编写，不套空人设。此前有用方法可融合/取代/新增为同一谱系，不保留“旧专家/新专家”两条可路由名单；去向账、恢复包和研究候选不是第二生产方案。

### 3.5 共享能力原子层：池的内部底座

专家池存专业角色，负责人池存组队流程，工具池存真实执行入口；共享原子层保存它们反复使用的构件。它不是新角色、新模型、新服务或第二目录。女娲治理同一 catalog 中的原子及其消费者，参谋部只校验锁定后的契约。

| 资产分类（不是最小粒度） | 共用内容示例 | 组装到哪里 | 必须保留的差异 |
|---|---|---|---|
| template | 课程五要素、需求四问、交接结构 | 专家/负责人/Brief | 各专业目标、输入、交付物与验收 |
| rule | PonyTail、白帽证据、真实完成、授权边界 | 所有适用角色和流程 | 不把每个角色职责合并成一人 |
| method | 根因实验、来源反证、素材权利核对 | 命中任务的专业方法 | 领域条件、参数、反例与版本 |
| workflow | 提交前校验、输入缺损回交、定向返工 | 负责人 DAG 片段 | 不同交付任务的成员及依赖 |
| graph-trait | 精确引用、版本、范围、生命周期、证据 | 各类型图/schema | 专属字段、状态机和写入责任 |
| validator | 哈希绑定、接口一致、必要验收项 | 编译、执行结果与发布检查 | 不用通用检查代替真实领域验证 |
| context-selector | 有界检索、局部失效、来源回读 | 角色输入/图谱查询 | 任务主输入、必需指令不得被摘要取代 |
| code-module | 幂等事件、路径校验、版本引用等内聚实现 | Rust核心/专业生态适配器明确接口 | 平台差异、错误语义和动作授权 |

styles保留纯表现差异，可引用允许的表现原子；不能覆写事实、权限和专业方法。上表的五要素、PonyTail、白帽、交接等是组合能力或资产分类；真正的最小语义原子见3.11—3.16及附录F。原子不等于一个包、一个文件、一次工具调用或一个子代理。

### 3.6 原子契约、范围和准入

每项定义包含：`atom_id`、`asset_class`、`operation_kind`、`version`、`schema_version`、`content_hash`、`owner`、`purpose`、`inputs`、`outputs`、`applicability`、`anti_triggers`、`dependencies`、`conflicts`、`required_checks`、`allowed_slots`、`provenance`、`license`、`tests`、`failure_policy`、`rollback_ref`。asset_class沿用3.5的分类；operation_kind表示独立判断/选择/变换/受控效果。依赖必须声明类型及精确发布版本；发现期可以写候选范围，运行锁文件不得含latest/浮动分支。

范围区分任务/项目、领域和已准入全局。跨角色可用不等于跨用户共享；实例数据、偏好、素材与凭据仍受 scope/ACL 限制。出处必须指向实际章节、上游提交或验证经验，不以高星或项目名替代依据。方法说明与代码执行资产分开记录：改写方法不能给未审核脚本开权限。

硬规则标 `required` 且不可被下层删除；可配置部分使用具名槽，记录合法范围。任务授权是上限，不由原子设置授予。新增工具/文件访问不能通过公共原子升级悄悄扩大。完整 Skill 作为调用来源时仍须遵守其必读资源和安全要求，不得仅取一句方法而忽略必需指令。

### 3.7 确定性组装，不靠模型临场混提示词

```text
课程基础模板 + 必需共同规则 + 适用领域原子
  + 专家专业差异 + 本次任务命中方法/风格
  -> 校验类型/范围/依赖/冲突/授权
  -> 有效契约 + 精确锁文件 + 逐字段来源表
  -> 最小任务投影 -> 宿主执行与验收
```

作者维护“引用 + 专业差异”，生成物只读。完整有效契约存于发布产物；运行时投影只取当前任务需要的部分，并保留必要硬规则、验收及回读句柄。同一输入定义、锁文件与编译器版本必须得到相同规范化内容及哈希；时间戳等运行信息不混入构建内容身份。

集合项按稳定ID去重；标量只能在允许槽显式设置；不可变字段的冲突直接失败。工作流组合须有具名节点和明确输入输出，不靠拼接文字形成顺序。同一原子经菱形路径引用一次，只保留其全部依赖出处；不同版本不得静默择新，须显式解决兼容性后再构建。互斥方法在任务选择时拒绝同时启用。

不设计万能提示词DSL、多重继承或任意执行的模板表达式。P1 冻结有限组合规则与字段schema；适配器不可自行定义另一套合并语义。

### 3.8 五要素与专业差异不因去重而消失

专家有效契约 = 五要素骨架 + 共同规则 + 领域方法 + 专业差异。负责人有效契约 = 同一骨架 + 组队/交接原子 + 条件成员引用 + 专属流程。图谱契约 = 共同对象信封 + 适用特征 + 专属字段/状态/写权。代码模块通过类型接口共享，不把源文件正文当作提示词原子。

例如长篇与短篇可以共用事实/原创边界、交接格式，却不能消除长篇的连续性管理或短篇的篇幅收束。ComfyUI 节点与视频导出可以共用版本绑定，但各自的真实验证不能统一成“文件存在”。复用的是重复部分，不是把专业能力平均化。

### 3.9 影响传播、锁定与撤回

每个生成字段保存来自哪个原子/专业差异及具体版本；反向依赖索引回答“升级这一项，哪些专家、负责人、图谱、工具契约、入口和测试受影响”。索引由定义生成，可重建；不是手工维护的又一份事实。

升级先计算传递影响闭包，重组全部受影响消费者，执行共用测试及各消费者的差异/边界测试，检查权限、专业职责、上下文和资源变化；影响范围未查清不得发布。未受影响内容复用已校验的不可变产物，不把局部升级变成全库重写。

验证通过后原子切换一个完整发布清单；之后新建的相关任务统一使用新发布，无须逐个专家人工复制。已有任务锁定 `catalog_release + atom_lock + compiler_version + schema_version`；继续原版或明确取消/重新计划，不在途中热换规则。安全撤销可阻止受影响的后续动作并留证据，但不能偷偷改契约重跑。恢复是切回已验证、未被安全撤销的完整发布，不独立拼出未经验证的版本组合。

### 3.10 原子化的止损条件

原子粒度是“可独立说明、验证且有实际复用价值的一项责任”，不是一行代码、每个字段或每句话。已有两个适用消费者，或属于课程骨架/安全不变量等确定共用基础，才优先抽取；只用一次的细节先留专业差异，不提前发明泛化层。

依赖图必须无环；P1按真实组装样本确定深度/扇出预算并给超限诊断。抽取前后比较重复量、热上下文、查找/构建耗时和可理解性；如果仅增加跳转而无收益，就内联或合并。允许合并原子、退役冗余原子，所有变更仍可查谱系。一个窄领域内聚模块可以比几十个细碎原子更合理。

### 3.11 四层结构：原子不是整包，也不是每个字

```text
L0 基础值与接口：精确引用、范围、证据、时间量、许可、主/约束输入
 -> L1 语义原子：一次独立检查、选择、变换或受控效果
 -> L2 组合能力包：五要素、白帽、PonyTail、交接、注册验证等
 -> L3 应用配方：专家、负责人、工具动作、图谱和交付工作流
```

L0不是执行池：例如ExactRef是一项有意义的精确版本引用，不把ID、版本号、每个字符分成工具。L1须能单独描述输入、输出、失败理由和适用范围。L2引用L1，不复制规则；L3选择L2和必要L1并添加专业差异。层级是编写和构建组织，不新增四级常驻角色。

五要素保留完整课程框架，但其角色边界、任务目标、输入缺损、步骤依赖、限制与验收等共用构件可以独立升级。课程的四问是组合包：目标、交付物、满意标准和误解风险分别输出独立对象，经版本化要求关联后才构成Brief。主理人复用专家的课程原则同样约束组装：引用同一专业ID，不克隆专家正文。

### 3.12 可判定的原子粒度与复合条款拆分

判据是“一个明确职责、一类结果、一种可定位的失败”，而不是字数少。一个原子允许依赖其他原子，但不能偷偷承担两个互不相关裁决。输入、输出或失败可独立变化的责任应拆开；业务必须共同提交的状态保持事务封装。

例如原有“核对来源、许可、权限和写入边界；无真实执行及验证回执不报完成”至少包含不同检查：来源是否可定位、许可是否适配、动作是否获授权、写目标是否在边界、执行身份是否真实、验证是否绑定当前产物。任意一项失败都要有具体原因，不能只返回white-hat-failed。

PonyTail拆为：直达路径适配、现有能力复用、无必要节点剪枝、必要验证配置、并行收益判定、重复内容消解、无进展停止等。它们组合成最小正确包，但不能把“少输出”误当全部职责。白帽组合包进一步引用证据/事实、授权/范围、风险/副作用、版本/真实性等原子。

输入“允许/不允许”、输出“PASS/FAIL”仍不够：必须带对象版本、scope、已观察前提、原因码和证据/缺口句柄。模型给出的判断是proposal或需复核的专业结论，不因写成布尔值就变确定性事实。

### 3.13 同一语义，多种表现和实现

| 表现 | 做什么 | 不能据此宣称 |
|---|---|---|
| 类型/schema | 规定数据与静态限制 | 数据合法就代表已经执行 |
| 确定性程序 | 检查版本/范围/哈希/依赖等可计算条件 | 所有审美和专业判断已自动保证 |
| 模型指令片段 | 要求角色进行专业判断或按边界创作 | 提示词等于强制沙箱或稳定算法 |
| 工具实现绑定 | 关联真实CLI/API/MCP/UI动作 | 换个入口就自动具备同样能力 |
| 测试与证据规则 | 验证上述表现及真实领域行为 | 单元/mock等于真实运行通过 |

所有表现引用同一个语义ID和版本，但不强求一个“万能函数”承包全部实现。共用非领域不变量由一个代码模块实现；平台/工具不同的动作绑定分别测。专业模型表现由来源和样例约束，不能假设模型输出确定性。跨表现更新进入同一个影响闭包，不只更新Markdown。

例如guard/upstream-current共享“输入必须是已采用的精确上游版本”语义：schema定义ExactRef，store核对有效版本，模型片段禁止拿旧摘要代替正式输入，工具适配读取指定产物；每种表现有匹配测试。哈希校验是另一原子，不把哈希正确误当上游已被采用。

### 3.14 最小装载不是128次推理或调用

候选清单留冷态。构建时解析L2/L3依赖与冲突；任务到达后选择专业配方和条件适用项，展开其必需依赖闭包，合并重复指令、形成一份有界执行契约。不得为每个原子启动模型、子代理、MCP服务或文件读取。

公共发布索引和原子实例值分开：不可变发布元数据可本地缓存，任务事实/授权/用户偏好必须按scope和有效期读取。共享只能消除指令重复，不能假设每个子代理都知道上一代理看到的指令。没有预算容纳必需依赖时拆任务或缩范围，不断开安全检查。

确定性前置检查可同进程批量运行；有副作用的动作仍按工作流节点和实际证据调度。原子数增加不应线性增加主线程热提示、常驻进程或代理数，必须测量实际投影及构建/查询成本。

### 3.15 深挖共有语义，但不共享错误的东西

语义比较至少看输入类型与单位、输出含义、前提、权威、scope、副作用、失败与验收。不同文字但同语义可归并；同名字段但语义不同不得合并。相似度检索只产候选，由专业差异复核，不自动蒸馏。

典型保护：用户确认、外部事实验证、模型推断是不同权威；源码内容哈希、契约身份哈希、凭据保护也不同。视频帧率和音频采样率仅共享精确时间运算，不共享业务合法范围。素材可读、已授权、已采用、质量通过、已导出分别判定。普通写作风格包不能替代小说连续性、平台内容方法或技术文档正确性。

共用规则不等于共用所有数据。角色共享模板时，私有用户偏好、客户材料、workspace路径、授权和任务状态不被带往其它项目。经验原子候选可以沉淀匿名方法，不把可识别的原文/个案混进全局包。

### 3.16 抽取落地规则：同一谱系，内聚实现

每项候选先给出来源条款/代码职责、消费者、单一输入输出、正反例、不可合并差异，再选择合并/新原子/保留专业差异/拒绝抽取。文字出现次数只是线索，不是语义等价或效果证据。附录F中的128项是初始设计候选，P0/P1允许按实际复用合并、删减或新增，不以数量为完成目标。

校验、领取、扣减预算、提交事件等可以各有逻辑责任，但必须在需要的同一SQLite事务内保持原子提交；不得各开CLI导致检查与使用之间竞态。真实外部调用不能与本地事务伪装成单一提交：先记录受控意图，真实调用后按回执/状态查询恢复，unknown不盲重试。

采用依赖最新版仍走12.5；原子化不等于重写成熟软件、复制第三方源码或靠拆提示词重现工具功能。专业实现由确定的模块/适配器承担，定义、证据和影响图统一，编写代码与测试全新进行。

## 4. 总体架构及技术栈

### 4.1 唯一主链

```text
自然语言 -> 阿极：需求/白帽/最小路径
  小任务 -> 直接答复或执行 -> 比例验证
  复杂任务 -> 负责人工作流/专家工具候选
    -> 参谋部校验图、范围、依赖、预算、领取资格
    -> Codex 原生工具/必要子代理执行
    -> 确定性检查/必要专业审查 -> 需求产物对账
    -> 阿极汇报 -> 释放资源 -> 有条件沉淀经验
```

参谋部不理解任意自然语言，也没有另一个常驻模型。阿极/负责人提出结构化语义；参谋部验证及推进合法状态。

### 4.2 选定技术栈

| 层 | 选定方式 | 边界 |
|---|---|---|
| 模型与交互 | Codex 原生主线程/工具/子代理 | 不新造宿主 |
| 确定性核心 | 全新Rust CLI及库模块，暂名wuji4 | 无常驻服务；短进程执行，不翻译或搬运3.0实现 |
| 契约 | JSON + JSON Schema，专业正文 Markdown | 一份权威，生成阅读表 |
| 本地状态 | 每工作区SQLite；同步Rust驱动优先rusqlite候选 | P0按上游资料锁版本/许可与构建链；bundled SQLite不冒称纯Rust依赖，不默认引入异步运行时 |
| 产物 | 工作区文件与哈希/引用 | 大正文不塞进数据库 |
| 检索 | 派生层级目录与本地查询 | 无向量判断模型 |
| 宿主适配 | 新写 Skill + wuji4 协议 | CLI 不能自证原生调用 |
| 软件工具 | 已验证 CLI/API/MCP/UI 入口 | 一个动作优先一种适配 |

成熟外部依赖可以正常使用，禁止复制此前项目的封装实现。SQLite 是单一事务状态层，不是第二套记忆权威。原子定义、组装配方和来源锁文件随 catalog 发布；编译物只读派生，不再单独维护模板/规则/专家中的重复正文。

### 4.3 权威与派生数据

catalog 内契约是角色/工具/规则定义权威；专业正文由契约引用，不重复整段文本。工作区 SQLite 管该项目任务事件、状态和授权。经授权晋升的用户/跨项目经验由用户应用目录内 shared-experience.sqlite 单独持有；同一经验只在其所属scope的库中拥有权威版本，项目只保存引用，不复制第二份可写事实。全局发布目录与工作区任务状态也不双写。检索目录、阅读表、看板自动派生，不手工维护不同事实。历史发布包仅用于恢复，不参与当前路由。

### 4.4 核心模块

catalog 管定义；selector 缩小候选；scheduler 管依赖领取；store 管事务；context 管局部投影；evidence 管产物验证；host 管宿主协议；governance 管准入经验发布。软件适配放 adapters，不反向改写调度或用户需求。

composer 负责原子解析、类型检查、确定性组装、来源映射与影响计算；作为CLI内普通模块运行，不是额外服务。通用代码优先复用已有内聚模块；只有明确重复与稳定接口才抽取，不新建无边界的 utils 仓库。

共享底座应覆盖intent/contract、reference/evidence、scope/authority、graph/version、execution/effects、context/query、artifact/acceptance、experience/release及专业基础算子；这些是有限职责模块，不是每原子一个目录/服务。具体候选与消费者见附录F。程序代码共享、专业提示共用和资料资产引用分别处理，不能混为一种“融合”。

### 4.5 研究先行与跨语言融合的默认解法

遇到新想法、技术选型、架构、融合、性能、兼容性或故障根因问题，先查同一来源账内有效结论，再全网找同类成功/失败实践，追到原始文档、作者经验、当前实现或原始研究，判断平台/版本/权限/副作用及资源约束是否匹配。有足够匹配依据时直接复用结论、方法或既有工具，不默认先写试验，不假定自己的想法独创；只有仍影响决定而外部证据未覆盖的具体缺口才做最小必要验证。

搜索不是每轮固定长篇调研或多评委。简单任务直达；已有有效结论不重复搜索；达到证据覆盖或新结果不改变决定时停止，不把本轮未找到说成世界上没有。研究记录question、decision_needed、prior_source_refs、matching_constraints、external_evidence_kind、counterevidence_refs、applicability、decision、remaining_gap、experiment_needed/reason，由同一G-RESEARCH/G-LINEAGE承接，不新增资料权威。

公开先例支持Rust共享核心与多语言接入，并不证明Rust在4.0所有指标上优于Go，也不把作者的历史计划当当前实现。不得把外部测试/采用情况登记成local-executed/local-accepted；本次成品、宿主身份、授权、额度与关闭状态仍按实际证据记账。选型论证的外部证据和本项目成果验收不是同一种验证。

融合分方法/知识、契约/资源、工具行为、专业内核四类。方法提炼进原子与专业配方；资产独立核权利/hash/版本；工具优先使用已有MCP/CLI/API，不要求Python/Node/Go项目改写成Rust。FFI仅在确有功能或有适用性能证据时使用，保留C ABI及内存/异常/线程边界，不把语言内部对象当跨语言协议。适配器不能直接写任务SQLite或引入第二代理宿主/数据库权威。

Rust核心用有限enum、身份newtype、受控构造/迁移与Result表达差异；任务、经验、来源、工具和发布各有类型，不合成万能状态机。业务核心禁止自行加入unsafe；必要FFI集中在小适配边界，依赖中的unsafe另核，不声称全依赖无unsafe。统一schema仍为契约字段单一维护源，Rust绑定和展开schema作为派生或一致性校验产物，避免再手写一套重复定义。

优先单一Cargo包的CLI/库与内聚模块；需要独立发布或明确稳定边界才拆crate，不按128候选创建128进程/crate/模型调用。SQLite短事务不等待模型/工具；默认不为同步本地状态添加Tokio、常驻HTTP或插件总线。已有标准接口能满足就不发明第二协议层。

## 5. 角色职责、写权与协作责任

### 5.1 角色不是模型配置

同一宿主模型可以在不同任务节点执行不同契约。MoE 在本文中是“选择少量相关角色/方法”的稀疏装载机制，不声称建立了神经网络 MoE 或改变模型内部结构。

| 角色 | 负责 | 不负责 | 默认形态 |
|---|---|---|---|
| 阿极 | 对话、理解需求、白帽判断、路由建议、最终汇报 | 代写所有专业细节、伪造宿主能力 | Codex 主线程 |
| 参谋部 | 图校验、依赖、领取、预算、回执、失效传播 | 另开模型、创作、最终主观验收 | 确定性程序 |
| 负责人 | 按交付目标选工作流、组织专家、整合交付 | 永久占有专家、擅自扩大权限 | 冷契约；必要时执行实例 |
| 专家 | 窄领域专业产物、工具流程、自检与交接 | 改用户要求、跨域偷做、自由派人 | 冷正文；选中才装载 |
| 女娲 | 目录治理、去重、融合、进化、退役、经验晋升 | 第二生产调度器、自动覆盖发布版本 | 事件触发任务 |
| 复合审查角色 | 按需要启用质量/安全/合规/性能/根因职权 | 常驻评委、代写、自由互调 | 一个可组合职责契约 |
| 宿主执行节点 | 真正调用工具/子代理、执行范围内动作 | 用准备记录冒充调用 | 原生调用或可验证工具动作 |
| 证据校验器 | schema、哈希、测试、版本、需求映射 | 替代所有审美判断 | 确定性程序 |

“阿极唯一沟通”是组织责任：最终答复和必要澄清归主线程。Codex 可能显示子代理进度及线程，这是宿主 UI，不承诺通过本项目隐藏。

### 5.2 写入必须通过确定性事务层

用户消息产生的需求变更由阿极提出；模型归纳只作提案。SQLite 写层校验范围、schema、expected_revision、幂等键、有效授权并提交。角色 owner 是业务责任，不等于可直接任意写数据库。

| 数据 | 变更提出方 | 提交/验证方 | 不变量 |
|---|---|---|---|
| 需求/用户决定 | 阿极 | store + 来源绑定 | 推断不能伪装用户决定 |
| 任务图/状态 | 负责人/宿主执行观察 | scheduler/store | 不接收过期版本回执 |
| 专业产物 | 被分配执行节点 | 文件边界 + evidence | 唯一目标 owner |
| 目录/规则发布 | 女娲提案 | admission + 回归 + 发布事务 | 运行任务版本固定 |
| 经验 | 执行/反馈事件 | 范围审查 + 脱敏 + 验证 | 不跨项目污染 |
| 验收 | 校验器/必要审查 | requirement-artifact 对账 | 主观高分不能覆盖硬失败 |

### 5.3 不建立第二指挥链

专家可以申请缺失输入/工具/跨域承接，但只回交负责人。负责人提出图修订，参谋部校验，阿极处理用户可见问题。互协通过正式产物接口完成，不让专家互聊构成无界循环。

所有角色必要时可有多个并发实例，例如多个负责人分别处理独立交付物、多个审查分支检查不同范围。但数据库事务仍序列化，用户决策仍只有一个入口。

写路径授权须考虑Windows大小写、符号链接/联接、UNC及盘符变化。默认禁止跨出批准根目录；文件边界不等于读取系统所有目录的权利。

### 5.4 池治理与全角色MoE，不重新建立主帅领地

阿极负责用户意图和必要路线判断；参谋部负责已确认计划的选择合法性、依赖和派发，不用本地小模型替它理解用户。负责人目录决定交付SOP，专家池决定专业能力，工具池决定真实动作，知识/经验池决定依据与适用做法，原子层提供共享定义。女娲与相应专业owner治理各池的准入/更新/退役，store/composer提交已验证版本；治理不是另一条任务指挥链。

新主帅在4.0对应“交付负责人/专家团配方”：定义长期存在于冷目录，成员实例和任务小队是按需短寿命的。不是每任务临时编组织，也不是负责人永久拥有一套专家。一个专家有一个权威定义，多位负责人按同一版本引用；组织经验归负责人配方，专业经验归相应专家/方法的scope。

阿极的专业增量、负责人、专家、女娲专项、复合官员/审查均按任务选择相关配方/职权，未用部分保持冷态。阿极主线程本身是沟通入口，不因此额外开一个“阿极MoE服务”；参谋部/校验器是程序，不伪造为模型专家。任意角色需要多个实例时，每实例有独立RoleTaskGraph，共享全任务预算，依赖正确、有收益才并发；多个负责人也适用。多实例不能克隆写权、用户决定或发布指针。

## 6. 负责人池、专家池、风格包和工具能力池

### 6.1 分类是索引，不是组织层级

```text
总目录 -> 能力领域 -> 专业簇 -> 专家叶节点
任务目录 -> 交付类型 -> 负责人/工作流 -> 条件专家引用
工具目录 -> 动作类型 -> 平台/格式 -> 已验证入口
```

一个专家只有一个权威定义，可以由多位负责人引用。多标签只产生索引引用，不复制正文。目录条目短摘要至少包含输入、输出、专长和排除项；按下一级读取，不一次装载全部专家。

### 6.4 风格包与方法包

风格包只含语气、审美、格式及示例，不能改权限、事实或专业验收。专业方法包含具体触发、步骤、证据、适用范围、反例。每任务只装载命中的包。

例如短篇小说专家可用悬疑/温情风格包；小红书专家的结构方法不能只当小说风格包。用户风格选择只在该项目/任务生效；只有明确约定的长期偏好才扩到用户范围。

### 6.5 工具能力池

统一记录：tool_id、类型、动作、输入输出 schema、版本锁、入口、平台、许可证、凭据引用、读写范围、费用/外部影响、并发安全、幂等/状态查询、健康时间、验证证据、兼容来源和失效条件。

工具状态：`discovered -> source-reviewed -> adapter-ready -> callable -> behavior-verified -> enabled`；失败可进入 `quarantined`。仅登记不启用；可调用也不代表每种任务都验证。

方法可融合；执行软件保留实际接口。相同动作有多个工具时按任务格式、验证状态、环境、授权、成本约束过滤；候选冲突回阿极/负责人，不用词面命中数伪装置信度。

### 6.6 知识库与经验池：关联而不混用

| 存储对象 | 内容与来源 | 读取/更新边界 |
|---|---|---|
| 知识库 KnowledgeRecord | 原始课程/文档、官方规则、技术说明、带出处的事实与方法；原文及结构化解释分开 | 来源版本/页段/hash、许可、权威、scope、时效、冲突；不把模型推断标成事实 |
| 经验池 ExperienceCandidate/Record | 实际交付中的纠正、成功/失败边界、组织经验、工具参数及明确用户偏好 | 触发条件、适用用户/项目/领域、反例、真实证据、验证/过期/撤销 |
| 任务事实 | 本次Brief、决策、素材采用、调用与产物 | 留在项目/任务scope，不自动进共享知识或经验 |

知识回答“依据是什么”，经验回答“在什么条件下怎么做有效”。两者各有schema、命名空间/类型、写owner、检索条件、权限与生命周期；可共用SQLite和派生索引，不增加两套数据库服务或常驻学习模型。知识沿G-RESEARCH与G-LINEAGE定位，经验沿G-EXPERIENCE；类型必须保留。

经验可以引用knowledge_id/exact_source_ref；知识变更使相关经验进入待复核，而不是无依据批量重写。经验提炼出的通用方法需经来源/范围/反例/专业验证才能成为知识候选或共享原子，单次用户偏好永不自动晋升普遍事实。检索按任务分别命中相关知识/经验，只将必要片段注入选中角色。

### 6.7 各池共同投影：brief / overview / source

负责人、专家、工具、知识、经验、方法/风格条目共用目录投影接口：brief只列专长/输入输出/反触发及句柄；overview按需列职责/条件流程/限制；source_ref指向版本化完整原文或可调用资产。这是装载层，不能与L0值/L1原子/L2包/L3配方混用名称。

类型/scope/交付明确时直接定位配方，跳过无收益的总目录逐层浏览；只有模糊或复合任务按类别下钻。摘要绑定source hash、发布/权限和有效期；不允许用过期摘要授权动作。多标签/别名只指向同一权威对象。目录视图沿已有G-LEAD/G-EXP/G-TOOL/G-RESEARCH/G-EXPERIENCE生成，不新增G-CATALOG/G-CONTEXT图服务或第二事实库。

### 6.8 工具动作：discover → inspect → bind → invoke → verify

先用宿主已支持的发现入口；仅缺口才评估lazy-tool/mcp-cli/标准适配。inspect读取当前server/tool/version/schema hash、身份/权限、健康与副作用；bind将真实接口及scope绑定ActionContract，invoke由原生宿主实际执行，verify校验结果。名称相似、仓库来源、enabled或检索命中不产生权限。

缓存按身份/scope/接口版本隔离；接口更新使旧契约失效。同名工具加命名空间，不默认fallback全目录，不自动启动全池MCP。不支持MCP Skills扩展时仍用本地冷目录/已验证MCP，不做宿主能力虚报；发现与分发标准不等于安全授权或执行成功。Comfy官方CLI/MCP明确本地目标，不按默认登录状态静默转收费云端。

### 6.9 专业细分与风格包的准入选择

输入输出、必要工具、专业流程或验收显著不同的任务簇可独立专家，例如长篇连续性、短篇结构、技术写作、对白、分镜、混音；仅语气/表现风格差异则用可选风格包，例如同一专业任务的幽默、克制或平台语气。不能把所有文案融合成万能专家，也不能为同一种能力每个风格克隆一位专家。

课程/用户明确的风格先进入Brief，由负责人/相关专家选择专业兼容包；包不能覆盖事实、版权、授权或专业验收。P0/P3据证据决定leaf/method/style/tool，不用固定专家数量替代专业覆盖。新增、合并、替换、退役都按同一五要素、图谱、原子引用、效果门和依赖影响流程，不能另建临时专家体系。

## 7. 图谱、关系与数据设计

### 7.1 图谱是逻辑视图，不是十几个数据库

各图共享版本化对象引用和审计事件，但有独立类型/写权。SQLite typed tables 是数据权威；图视图由同一数据生成。可派生内容完全可重建。

| 图 ID | 回答的问题 | 主要对象/关键字段 | 生命周期 |
|---|---|---|---|
| G-REQ | 用户真正要什么 | requirement_id、目标、约束、来源、验收、未决项 | 项目期 |
| G-DEC | 什么决定已生效 | decision_id、消息定位、scope、替代决定 | 项目期，可撤销 |
| G-LEAD | 什么任务找谁组队 | task_type、workflow_id、负责人、条件成员 | 发布版 |
| G-EXP | 哪位专家胜任 | specialty、输入输出、方法、排除、工具引用 | 发布版 |
| G-TOOL | 什么工具可用 | action、版本、平台、状态、依赖、验证 | 版本+健康期限 |
| G-ROLE | 每个角色做什么 | role_instance、parent_graph、node、depends_on | 短寿命 |
| G-EXEC | 执行进度与尝试 | task/node/attempt、lease、版本、预算、事件 | 任务期 |
| G-ACCEPT | 要求是否真正完成 | requirement→artifact→validation、缺口 | 项目期 |
| G-CODE | 代码和变更关系 | 文件/符号/导入/测试/哈希/影响 | 可重建 |
| G-RESEARCH | 声明依据及反证 | claim、source、日期、范围、excerpt_ref | 任务/资料期 |
| G-INCIDENT | 为什么失败 | symptom、hypothesis、experiment、root_cause | 事件期 |
| G-EXPERIENCE | 什么经验适用 | 类型、范围、条件、反例、验证、TTL | 治理后长期 |
| G-LINEAGE | 技术融合到哪里及升级影响谁 | 来源/经验→原子→组装→消费者/测试；版本/许可/替代关系 | 发布审计 |
| G-RISK | 风险和义务是什么 | 资产、信任边界、权限、版权、控制、证据 | 按敏感级别 |
| G-REVIEW | 审查意见是什么 | 原始要求、产物哈希、发现、职权、verdict | 审查实例 |
| G-PERF | 是否高效 | 工作负载、工具/节点延迟、资源、可见遥测 | 聚合+期限 |

### 7.2 所有对象共同字段

```text
id: 唯一ID；type: 类型；scope: 项目/任务/用户/已准入共享
schema_version: 契约版本；revision: 当前修订；owner: 业务责任
authority: 用户明确/工具观察/外部证据/模型推断/审查建议
status: 生命周期；source_refs[]: 来源定位；evidence_refs[]: 证据引用
created_at/updated_at/valid_until: 时间；classification: 敏感级别
content_hash: 完整性；parent_refs[]: 精确上游版本
```

秘密不进图，使用不透明凭据引用。哈希证明完整性，不证明授权、独立性或来源真实性。敏感内容不要用可猜测的裸哈希替代隐私保护。

### 7.3 typed tables 与唯一约束

| 表组 | 关键主键/约束 | 事务责任 |
|---|---|---|
| scopes / decisions / requirements | requirement(scope,id,revision)，有效修订唯一 | 决定与需求投影一起提交 |
| tasks / role_graphs / task_nodes / edges | node(task,id,revision)，依赖无环 | 图变更与下游失效原子提交 |
| attempts / leases / execution_events | attempt UUID，事件幂等键唯一 | 领取/续租/释放/CAS 状态迁移 |
| artifacts / validations / acceptance_links | artifact版本不可覆盖；验证绑定当前哈希 | 验证通过才更新验收投影 |
| source_registry / catalog_versions | 来源标识+定位+哈希，发布ID唯一 | 契约/索引发布一致 |
| experiences / experience_evidence | scope+类型+归一化键，撤销状态明确 | 候选/晋升/替代/撤销事务 |
| risks / review_findings / audit_events | 发现与产物版本绑定，追加审计 | 读写/授权/删除均留最小审计 |
| indexes / metrics | 标记 derived，源修订可追溯 | 可重建，不成为第二事实来源 |

不采用“万能 graph_nodes 放任意 JSON”代替业务 schema。共用引用表可以存在，但核心状态用类型和数据库约束保证。

### 7.4 关系词及校验

允许：`depends-on`、`produces`、`validates`、`derives-from`、`uses-tool`、`uses-expert`、`implements`、`affects`、`supersedes`、`governed-by`、`uses-atom`、`composes`、`specializes`。关系必须验证两端类型、scope 和具体修订；禁止随意新造语义。原子关系服务发布影响分析，不作为另一套运行调度边。

### 7.5 查询路径与预算

先 scope/类型/类别过滤，再下钻叶节点，读取必要正文，最后沿明确依赖扩展。每次声明目的、最大结果、跳数、字节及时间。预算到界返回 truncated 与回读句柄，不静默丢弃。

纯聊天不查整池；清晰任务直接定位；模糊任务给阿极少量候选及差异。不以模型“觉得很相关”绕过跨项目 ACL。

### 7.6 失效传播与例子

需求修订 → 引用该要求的节点及后继失效；资产更新 → 使用该资产的镜头/生成单元/剪辑片段失效；时间线变更 → 受影响音轨和导出失效；来源过期 → 对应规则待复验，不自动修改在途任务；验收报告只绑定当前产物哈希。

例如用户把第 3 镜台词换掉：只重配该对白及相关声场、字幕和最终导出，不重新生成无关图片/BGM。不允许旧版本晚到回执把新任务标为完成。

### 7.7 全角色任务图轻量化

每个激活角色都有 role_graph_id、parent_graph_id、职责节点、输入句柄、版本、状态和验收；小任务可以只有一个内存节点。任务进入可恢复执行或产生持久产物时才写库。参谋部的图是调度处理记录，不表示独立模型跑过。

### 7.8 原子依赖与反向影响视图

共用 G-LINEAGE，不再添加第17个图服务。权威是 catalog 的版本化原子和组装引用；`atom_dependencies`、`consumer_atom_refs`、`composition_outputs`、`reverse_impacts` 是发布构建生成的只读视图，标记 source_release/hash，可完全重建。

```text
技术来源/验证经验 -> 共享原子 -> 专家/负责人/流程/图谱/校验器
                         <- 精确版本引用与反向影响索引 -> 必须重跑的测试
```

升级计划包含 changed_atoms、transitive_consumers、required_tests、permission_diff、context_diff、schema_migration、rollback_release。遇循环、悬空引用、版本冲突或跨scope无权引用直接失败，不能绕过索引靠猜测改几个专家。

依赖影响查询与普通任务检索不同：日常任务继续遵守小结果预算；发布升级须用有界分页遍历全部影响闭包，最终输出完整性校验，不能把“最多20对象”的截断结果当全部影响。索引损坏可重建，但未经完整计算不得发布。

## 8. 任务生命周期、并发和执行回执

### 8.1 三类入口

- S0 聊天/简单文本：阿极直接处理，不创建 staff 工作流，不读全目录。
- S1 单领域有界动作：最少专家方法和工具，由阿极执行；需要写入/取消/证据时记录轻量任务。
- S2 多步、跨领域、较高风险：负责人 DAG + 参谋部验证；按需多子代理。

升档依据任务依赖、交付形态、权限风险，不按固定字数。阿极提出类型；程序检查动作约束，不能把程序描述为自动理解所有任务。

### 8.2 任务节点状态

`planned -> ready -> claimed -> running -> produced -> validating -> succeeded`。

另有 `blocked`、`failed`、`cancel_requested`、`cancelled`、`superseded`。blocked 是资料/权限/能力等前置缺口，不等同程序异常。produced 不等同 succeeded。图 revision 和 attempt 必须分别校验。

### 8.3 领取与回执协议

1. 校验输入、依赖、写范围、预算、当前 revision 和宿主能力。
2. 短事务领取lease、预留全任务共享的宿主槽位和资源预算，生成invocation_contract；复核能力观察的新鲜度。并发领取不得重复使用同一空闲额度。事务不跨网络/模型等待。
3. 宿主实际调用，记录 host_execution_id 或实际工具事件标识；没有则只允许 prepared 状态。
4. 回执带 attempt/版本、输出句柄、结果状态、失败种类和可见宿主观察。
5. 重新验证哈希、文件范围和任务验收，CAS更新状态，释放任务lease；宿主槽位另按8.6关闭确认释放，不能因业务节点完成就视为线程关闭。
6. 超时/断线先查询执行状态。不能对未知完成状态的付费动作盲目再次提交。

调用前崩溃、调用后未记账、回执重复、租约过期、跨版本晚回执都必须有故障注入测试。

### 8.4 并发资格

子任务自包含、没有依赖等待、写集合不冲突、预算有收益、宿主允许时才并发。预算由所有角色共享，不按角色各开一份上限。相同文件不同区域默认仍冲突，除非实际隔离到不同产物并明确整合 owner。

大型源码实现分独立文件集合；最终集成节点只在全部必需上游完成后运行。数据库写入短事务，不把模型思考锁在 SQLite 内。

### 8.5 重试、返工和熔断

失败分资料/权限/能力/确定性缺陷/瞬时网络/未知提交状态/专业质量。相同输入和策略无新证据不再跑。瞬时重试需同一幂等键和可验证原因；质量返工退原 owner 的明确缺陷范围。

初始策略：单节点最多 2 次定点修订；整任务额外重试最多 6 次，连续 2 次无验证进展暂停。正常节点的首次执行按已批准 DAG 节点数计入基础预算，不被这 6 次额度截断。均为工程初值，可因范围配置；不得改节点ID绕过总预算。领域重建是显式计划修订，不自动清空全部成果。

确定性 verdict：PASS/REVISE/BLOCKED/REBUILD。PASS 必须满足当前验收；REBUILD 只针对受损结构，不无限追加轮次。用户有新要求时更新需求及预算，而不是当成同一次失败。

### 8.6 子代理退出

任务完成/失败/取消后由宿主适配发起可用的停止/关闭动作并记录宿主结果，清理局部上下文、lease、临时资源。不支持的退出接口必须标`release_unverified`；不宣称“已真退出”。正常完成但尚未关闭、正在关闭及释放未确认的子代理，仍计入宿主开放槽位，不得重复分配。关闭请求被接收不一定证明槽位已释放；按实际接口语义或后续有效观察确认，迟迟未确认则排队/串行并报告。

角色图层级不等于原生spawn嵌套深度。负责人契约可以由主线程执行并扁平派发专家；任何层级的角色实例都共享同一宿主额度，不需要为组织层级创建对应深度的子代理。

## 9. 上下文、预算与资源管理

### 9.1 只加载必要内容

稳定共同规则 → 当前角色短契约 → 当前节点输入/约束 → 命中方法 → 必要原文句柄。主线程保留要求、版本、路径、短摘要和状态，不粘贴所有专家正文。原始产物仍可按需读取，摘要不能替代源码、台词、模型参数等主输入。

原子引用可以减少存储和维护重复，但不代表模型能只凭ID知道正文。首次相关执行必须得到已组装的必要指令或实际读取其句柄；跨子代理不假定共享记忆或缓存。原子目录留冷态，不能因“共享”把全池注入每个角色。

冷态只保证4.0未选角色的正文/执行资源不装载，不意味着宿主已有工具说明、全局Skill元数据和旧会话历史消失。性能报告单独测量可控制的增量，不能宣称移除了Codex系统上下文。

### 9.2 初始工程预算（不是模型事实）

| 项目 | 初始值/策略 | 超限处理 |
|---|---|---|
| 冷目录候选 | 单次最多 5 个 | 缩小类别或回阿极判断 |
| 图关系查询 | 默认 2 跳、最多 20 对象 | 返回遗漏说明和显式继续入口 |
| 热方法 | 默认 1-2 项 | 拆节点或改用句柄，不删安全字段 |
| 上下文目标 | role/contract 约 4 KiB、证据约 8 KiB | 目标值，不是绝对硬门；按自包含性调整 |
| 并发子代理 | 默认2；2026-10-02用户/项目配置cap均为3，非永久硬顶 | 按9.5有效额度钳制；压力1；无可靠余量则排队/串行 |
| 大型生成/渲染 | 默认同时 1 个 | 明确有容量才增加 |
| 工具大输出 | 有界摘要+原始制品 | 列出省略、原文、错误；不可破坏解析 |
| 空闲运行 | 不保留 wuji4 常驻进程 | 回归测试检查残留 |

预算按字节和可观测 tokens 分开记录，中文 UTF-8 字节不是字数。历史 2048/4096 限制不照搬；任何硬上限必须有宿主限制或实测工程理由。不能为了装下契约删掉验收、权限或必要代码。

### 9.3 资源与清理

无默认 watcher、轮询、MCP 全池启动、模型服务。工具按动作启动，声明进程 owner、取消方法和最大持续时间。只关闭本任务创建并确认归属的进程，不按通用进程名杀掉用户软件。

派生索引惰性重建、源文件变动局部更新；原始库不每任务全盘哈希。缓存按工作区、版本和内容键隔离；失败或状态未知的执行结果不能命中成功缓存。

### 9.4 上下文压缩边界

本项目可以减少重复输入/工具输出，不能声称修复宿主 remote compaction。出现宿主压缩错误时保留最小可恢复检查点、错误和版本，停止空转；宿主问题独立诊断，不往军团核心塞二进制补丁。

### 9.5 宿主基线、有效预算与并发准入

以下为2026-10-02独立核验记录，不是永久限额或4.0运行实测。P0重新读取当前有效配置，记录用户/项目/profile/启动覆盖及项目受信任情况；桌面会话有效值无法观察时明确unknown，不从磁盘文件存在推断已经加载。

| 项目 | 核验基线 | 真实语义与4.0用法 |
|---|---|---|
| agents.max_concurrent_threads_per_session | 用户与项目配置均3 | 不含主线程的开放子代理上限；默认策略2，实际按有效额度准入 |
| tool_output_token_limit | 用户与项目均4096 tokens | 单项工具/函数输出保存在历史中的预算，不是完整回执/制品文件上限 |
| model_auto_compact_token_limit / scope | 用户240000；项目90000、body_after_prefix | 自动历史压缩触发值及计数范围，不是任务总token或计费上限；有效层待观测 |
| 模型context window | 本地所列模型为272000；未列gpt-6.1-sol | 不能套用于所请求第三方模型；窗口/模型来源和有效性分开记录 |
| skills.max_context_tokens | 官方默认有效窗口2%；显式设值上限10000 | 整体可用Skill目录表示预算；只有有效窗口确为272000时才可推导5440 |
| agents.default_subagent_model / default_subagent_reasoning_effort | 官方存在 | 生成代理默认值；显式spawn选择优先，不等于逐任务三档策略已实现 |
| agents.max_depth | 本机配置1；官方参考表未列 | 未文档化/未验证；须核对安装版schema/解析/行为，不断言无效或生效 |
| CLI入口 | 2026-10-03只读观察codex-cli 0.160.0，历史观察见22.4 | 记录实际路径/版本/动作；帮助与配置不冒充有效请求，不固定安装散列目录 |

并发准入：`cap = min(policy_cap, effective_host_cap, resource_cap)`；`可新建数 = max(0, cap - 已占用及已预留槽位数)`。已占用/预留用互斥状态集合统计，包含running、完成未关、closing、release_unverified、dispatch_reserved；同一线程不得双计。宿主其他已打开代理也占用额度，不能只数4.0业务节点。

适配层用宿主可见代理ID/状态或有效配额事件核对，scheduler在短事务中预留；调用失败后确认未创建线程才退还预留，提交状态unknown则查询/对账。观察不到全会话余量时不猜有空槽，保守单路申请并处理真实quota拒绝/排队；这种保守尝试不等于保证成功。调低额度不强杀用户线程，停止新增直到占用回落。

完整回执和制品保留在权限内的证据存储，工具返回有界摘要、完整记录句柄/hash和省略说明；不能为4096 tokens截坏JSON、抹掉失败或删证据。Skill入口数量及实际目录投影单独测量；不把所有叶专家注册成全局Skill，也不靠裁去安全字段挤预算。若未证实实际目录预算，只有暂定目标，不声称已达硬门。

KiB/bytes是序列化或UTF-8大小；tokens是指定计数器或宿主可见计量，二者不得互换。上下文容量、压缩阈值、历史输出预算、目录表示及单任务成本各有独立单位/来源/有效层；缺token/计费遥测不能声称已强制账单限额。宿主/配置/provider/模型/工具schema变更使相关缓存观察失效，下一次调用前重新核查。

### 9.6 少加载还要少往返，PonyTail贯穿表达与程序

运行只展开当前配方必需依赖一次，组装成一份有界热契约；不为每原子开工具调用/模型/子代理。候选语义可在构建时细分，实现保持内聚，未准入原子不进入热链。只有brief不足完成当前任务时才读overview/source，专业原文、源码和强制条件必须实际提供，不能用ID假定模型知道。

同时测定位往返次数、实际注入字节/可见tokens、总耗时及产物效果；减少热正文却增加无收益检索回合不是自动成功。清晰小问题直接简答，长文仅在用户要详细文档时展开；复杂工作短报进展、详细证据落文件。少推理/短代码是最小正确策略，不承诺宿主medium实际零推理，不用代码高尔夫或压缩不可读代码冒充优化。

## 10. 预定义业务工作流

### 10.1 所有工作流共同门

Brief 用课程四问：要什么结果、交什么东西、怎么算满意、哪里容易理解错。缺信息先判断能否安全采用已说明的默认值；只有影响授权/关键方向/成本/不可逆动作才请求用户决定，不每阶段机械追问。

每条边有主输入、约束输入、产物版本和验收。内容确认、执行授权、实际结果采用分开记录；用户已委托的有界行动无需反复确认，但不可把内容认可当额外付费/发布许可。

### 10.2 WF-COMFY：ComfyUI 插件分析、逆推、蒸馏及开发

| 阶段 | 责任 | 输入→输出 | 阶段门/并行 |
|---|---|---|---|
| C0 范围 | 阿极/负责人 | 用户目的/授权→行为范围与交付要求 | 不绕过授权/许可/保护 |
| C1 证据 | node-analysis/workflow-analysis | 源码/运行/版本→注册表、数据流、行为契约 | 分析独立插件可并行，结果需对齐 |
| C2 融合 | fusion-design/architecture | 行为差异→目标接口、去重、保持项 | 不把多实现并排包装当融合 |
| C3 环境/API | packaging/API调查 | 当前目标版本→环境锁/节点与前端接口 | 不能凭记忆写“最新规则” |
| C4 实现 | 必要语言/前端专家 | 锁定接口→源码/独立模块测试 | 文件集合不重叠才并行 |
| C5 集成 | integration-test | 实现→节点注册/真实最小图/边界图 | Python/Rust/C++ FFI 等需实际跑 |
| C6 质量 | 验证/必要代码审查 | 目标基线→正确性/性能/兼容证据 | 有性能目标才跑基准 |
| C7 交付 | 负责人/打包执行节点 | 验收通过→可安装包、工作流、说明 | 独立环境安装，资源可取消 |

ComfyUI等专业任务仍以Python等目标生态最小实现为先；军团确定性核心采用Rust不意味着所有专业项目Rust化。其它语言/FFI只有明确功能、协议边界或适用性能证据才加入；先查已有实现经验，不为体现语言实力强行四语言协作。

逆推优先外部行为、公开接口及有授权代码。可以独立重建功能，不要求逐字复制；第三方代码/素材必须明确许可，不能把“参考蒸馏”当规避版权的理由。

### 10.3 WF-SOFTWARE / WF-BUGFIX

新开发：行为定义 → 最小架构/语言边界 → 独立模块实现 → 集成 → 文档和包。

Bug：取得可复现症状 → 固定环境 → 假设/实验/反证 → 根因 → 最小修改 → 新写回归 → 受影响工作流。无法复现时交付已做检查和不确定性，不先改一堆代码。

根因、性能、依赖等调查可拆独立只读分支；同一根因修复只设一个写 owner。恢复已有功能与用户新增功能分开验收，防止借修 Bug 擅自重写全部产品。

### 10.4 WF-VIDEO：覆盖所有视频类型的联合流程

范围包括叙事短片、漫剧、文旅、纪录/科普解说、商业宣传、小说推文、MV、片花、片头片尾、动态包装。类型改变的是条件节点及方法包，不是建立一套永久专属人员。

#### V0 情报、目标和表达

收集资料/素材与版权，明确观众、平台、画幅、时长、预算、真实/虚构边界、叙事或解说、人称、讲述身份、声音主导方式和风格。文旅可使用人/事/景/物分类，其他题材按适配场景分类，不强塞八槽。

产物 `CreativeBrief`：confirmed_facts、source_refs、audience、intent、format、perspective、narrator_identity、expression、style、duration_target、budget、rights、acceptance。

#### V1 文案/故事及情绪曲线

对应窄领域写作专家完成正文；narrative-rhythm 制定段落功能、冲突/信息、情绪能量、留白和关键锚点。可以倒叙/插叙/蒙太奇，不从原文首段机械演到尾段。

长短篇、商业文案、解说和对白不全部压进“漫剧编剧”。既有原文与原创设定的真相边界分开，不能为了反套路改掉不可变事实。

产物 `StoryPlan`：文本版本、段落ID、目标时长、叙事功能、情绪曲线、不可改事实/结尾、台词与旁白的职责分界。

#### V2 分段音乐与预剪节奏（在详细分镜前）

bgm-cues 根据剧情决定 music-led/dialogue-led/mixed；选取可用且有权利的音乐、同曲段落或多曲 cue。以叙事段落和情绪变化换音乐，不按每几秒机械切歌，也不一首硬铺所有场景。

产物 `MusicCuePlan`：cue_id、叙事段、情绪/密度、入出点、过渡、音乐资产/许可、对白让位、节拍/乐句标记、锁定级别。

具备实际音频、明确节拍/乐句和可靠编辑入口时，先建立预剪/animatic；只是“想要某种音乐”还不是音频驱动的时间基准。

#### V3 风格资产与详细分镜

视觉资产、音色身份形成稳定 ID 和版本；montage-board/camera-design 在已确认文案、节奏与音乐 cue 约束下输出 ShotPlan，选择景别、运镜、蒙太奇、时间线重排和声音意图。

ShotPlan：shot_id、story_segment_id、start/end、camera、action、visual_asset_refs、dialogue/srt_ref、music_cue_ref、sound_intent、transition、invariant、generation_requirements。

台词、字幕和声音锚点必须对应具体镜头/时间段。叙事段落时长、生成单元时长、成片时间线时长分别保存，不能把模型单次档位当剧本节奏。

片头片尾/包装任务可以不调用小说专家、角色库或完整世界观；但仍需信息层级、节奏、资产和导出约束。

#### V4 能力档案与真实生成

image/video/audio 适配专家从当前接口建立提供商+模型+模式+关键参数能力档案，确认参考要求、时长控制、声音同步、输出格式和费用。字段/参数未核实不进入付费批量。

I2V 先有已采用的首帧/参考图；纯 T2V 不人为强制图像前置。图像/视频提示词设计可并行，实际生成依赖必须成立。实际文件经过解码、尺寸/时长、内容/身份/质量检查后成为 adopted，而不是文件存在即通过。

#### V5 粗剪、精剪和时间线版本

timeline-edit 使用已采用素材，按 Story/Shot/MusicCue 组接，调整停留/速度/切点，保留变速和重生成的理由。精剪不能擅自更改已确认的事实或故事终点。

时间线版本必须明确素材入出点、转场、字幕、音乐 cue、retiming map、帧率/时间基。更改时间线只使受影响音轨/字幕/导出失效。

#### V6 完整声音域与专业声场

声音交付 owner 按需引用 voice、alignment、ambience、foley、music、spatial、mix 等共享专家，统一交回版本化声音包，而不是多个小组分别裁决成片。

分轨：DX 对白/旁白、AMB 环境、FX/FOLEY 音效拟音、MX 音乐、BUS 总线。声场设计绑定具体时间线：pan/距离/混响/运动、room tone、J/L cut、crossfade、ducking、声音连续性和峰值/响度目标。

立体声左右移动不等于真实三维/前后定位。需要双耳/HRTF/多声道时先验证插件、格式及播放目标；不能把普通 pan 宣称专业三维声场。

#### V7 合入、终检和可编辑交付

剪辑 owner 合入已验证混音，检查画幅、同步、字幕、音量、色彩、黑帧、缺素材、工程路径和可再编辑性。交付成片、支持的剪映工程/草稿、REAPER 工程、分轨音频、SRT、资产与版权表。

某格式适配不支持时如实降级为已验证的中间时间线/分轨，并标明“未完成剪映导入”，不说能完成剪映全部功能。

### 10.4.1 视频跨池协作与音乐前置的正式交接

不是把全部视频能力集中到音频专家，也不创建永久“漫剧编制”。lead.video引用写作/研究/视觉/video/audio工具与专家池的同一权威定义，按任务SOP组织；故事、音乐、镜头、时间线和声音分别有产物owner，但最终交付责任唯一。

| 交接阶段 | 主要职责/条件成员 | 主输入→正式交付 | 串并行与返工 |
|---|---|---|---|
| Brief与情报 | lead.video + creative-research/相关研究专家 | 用户目的/证据→CreativeBrief | 独立资料可并行；视角/身份/风格冲突回阿极，不让专家自行改用户决定 |
| 基础故事与节奏 | 对应写作叶节点 + narrative-rhythm | Brief/原文→StoryPlan与情绪段 | 写作与节奏互校；先有故事/表达意图，不先选歌强编剧情 |
| 音乐cue/预演 | bgm-cues，必要时music-production/对白预演/timeline-edit | StoryPlan/情绪→MusicCuePlan、真实音频与预剪基准 | 详细分镜前完成必要音乐标记；占位音乐不算真实音频驱动；对白预演不冒充最终配音 |
| 视觉与详细分镜 | montage-board/camera-design + 相关视觉专家 | StoryPlan/MusicCue/已选风格→ShotPlan与资产规格 | 稳定风格资产可提前独立制作；依赖音乐的镜头时序不越门 |
| 生成与素材采用 | image/video适配专家 + asset-review | ShotPlan/能力档案→文件与Adoption记录 | 无依赖镜头可并发；I2V等实际前置满足；不把prompt当视频 |
| 时间线剪辑 | timeline-edit，必要subtitle/color/motion | 已采用素材/三计划→TimelineManifest、retiming_map | 依据剧情/乐句/对白留白剪辑；不要求每拍必切；必要变速/重生成退相关owner |
| 专业声音 | 一个sound-delivery owner + voice/alignment/ambience/foley/spatial/mix | 锁定时间线/SRT/音乐cue→SoundPackage与分轨工程 | 时间线相关最终声音在依赖完成后运行；独立素材可准备；对白/声场/BGM互相让位 |
| 合入与验收 | 剪辑执行owner + export-qa/必要审查 | 验证声音包/时间线→可编辑工程、成片和验收 | 仅全部必需依赖满足才合入；lead.video统一对账，不能多小组分别宣布完成 |

正式接口最少保存：StoryPlan文本版本/叙事段/不可变事实；MusicCuePlan资产hash/许可/cue段/乐句锚点/情绪/过渡；ShotPlan故事段/音乐cue/台词及镜头锚点；TimelineManifest帧率/时间基/片段/变速映射/revision；SoundPackage对白/SRT引用、各stem/bus/自动化、目标时间线版本及验证。各交接按课程主输入/约束输入区分，不把风格覆盖原文真相。

音乐在基础StoryPlan/情绪之后、详细分镜之前；音乐-led可反向要求局部文案/节奏适配，但不可改已确认事实/结尾。音乐随叙事段落适度变化，多曲或同曲不同段都可，留白/对白/环境声也是节奏，不按统一BPM机械剪。按既有视频替声或包装任务可选10.5条件分支，不让所有用户承担完整前期制作成本。

变更必须回传：故事/表达改动复核关联情绪、cue与镜头；cue节奏/长度/入出点改动复核关联分镜、预剪及时间线，必要时重生成相关素材；时间线改动复核字幕/对白/空间自动化/混音/导出；声音局部修改只退对应stem或合入。使用引用/消费者闭包判定，既不全片重做，也不只改BGM而漏掉同步关系。重大业务方向回阿极确认，普通契约内定点修正不逐步问用户选专家。

### 10.5 两种音画路径的明确选择

| 路径 | 前提 | 执行顺序 | 不允许 |
|---|---|---|---|
| 音频驱动 | 有实际音乐/节奏标记、表达允许 | 故事→情绪→音乐cue/预剪→分镜→素材→精剪→声场 | 用单一BPM控制所有戏剧节奏 |
| 时间线先行替声 | 现有视频或用户指定稳妥路径 | 已剪时间线→抽离/整理声音→按SRT/镜头配音→声场→BGM→合入 | 把SRT时段当保证口型一致 |

对白严格匹配 SRT 时窗须验证发音时长、说话人、停顿和画面口型。超窗时可在允许范围调整语速、修正文案或报告需要调整时间线，不能无证据宣称自动完美对齐。

两条是同一工作流的明确条件分支，不是两套专家方案。默认不为每任务同时跑两条对比。

### 10.6 WF-OFFICE / WF-DATA

输入文件范围/指标口径 → 数据读取清洗 → 计算 → 内容结构 → 对应 DOCX/XLSX/PPTX/PDF/HTML 实现 → 渲染/公式/链接/版式验证 → 交付。

数据计算和无依赖的视觉草稿可并行；最终报告引用必须等计算结果。OfficeCLI 只在其当前入口真实支持的动作上使用，不替代所有文档工具。批量重命名先生成目标清单、检测冲突，再有界执行并提供恢复映射。

### 10.7 WF-WRITING / WF-RESEARCH / WF-LEARNING

写作：事实/设定与受众 → 匹配专项 → 结构 → 正文 → 编辑/核对；不因“文案”一词调用所有写作专家。

研究：问题与约束 → 已有有效来源账 → 全网同类成功/失败实践 → 官方/原始/当前实现 → 声明/反证/日期/适用性 → 复用结论或限缩证据缺口。仅缺口影响决定时做最小必要验证；已有匹配实践不重复造实验。资料无法抽取时记录原因，不用标题补正文；普通问题不强制全网扫描。

教学：学员/可测成果 → 大纲 → 学习材料/练习 → 检查与反馈；模板与一次讲解分开。知识库问答保留出处，资料未覆盖就说明。

### 10.8 WF-BUSINESS / WF-AUTOMATION / WF-PUBLISH

商单：课程四问 → 流程/资源/风险/报价 → 授权和合同条款检查 → 交付验收/回款记录。不把参考金额当真实报价事实。

自动化：触发、目标目录、动作、权限、输出、失败通知、重复执行规则 → 使用宿主提供的排程机制 → 验证实际回执；不自建隐形轮询器。

发布：已采用定稿 → 平台物料和账号权限 → 草稿/发布授权 → 实际动作 → 链接/状态核验。用户要求“建议”不代表可以发布、发送或付费。

## 11. 白帽、铁律与规则优先级

### 11.1 优先级

宿主安全/权限 → 用户明确要求 → 当前任务授权与验收 → 专业契约 → 已验证共同规则 → 风格和经验建议。冲突时记录规则ID及原因，不能靠提示词中“必须”数量竞争。

规则类型：`hard-boundary`（程序可阻断）、`task-requirement`（本任务验收）、`professional-method`（条件方法）、`preference`（可改偏好）、`unverified-candidate`（不得直接执行）。

### 11.2 阿极的白帽不是另一位常驻官员

收到要求时按风险比例检查：目的是否一致、前提是否有证据、资料是否真的可读、能力是否可调用、权限/费用/删除风险、最简单可行路径、如何证明完成。

只把影响结论的白帽判断简要说给用户；不每轮输出七项表格或唱反调。复杂/高风险任务可用独立审查实例，普通聊天不启动评委团。

例：“用这个模型生成免费视频”先核实入口和费用；“这些声音从左到右”可做立体声 pan，但不冒充真实三维；“分析”只读，不直接实施修复。

### 11.3 共同铁律

| 规则 ID | 规则 | 落实位置 |
|---|---|---|
| IR01 | 最小正确路径，少解释少装载，但不省必要证据 | Skill/契约/性能测试 |
| IR02 | 唯一用户入口、唯一当前目录/状态链 | 注册表校验/主线程协议 |

### 12.5 最新核实、技术保留与原子承接

104项来源是基线而非全集上限。P0还须在经确认的2.0/3.0及其它参考版本中查来源账、出处、有效方法、资产和失败证据，补漏并归一化；不把它们的实现包搬进4.0。过往已经融合的有用技术可以保留其价值，但需重新追到原始来源、审查当前变化、独立编写共享原子或适配。查不到来源就明确缺口，不把“曾蒸馏”当可信证明。

如果最新版破坏现有接口、许可不适用或未通过真实验证，可以暂用已验证兼容版或不采用，必须有理由、复验条件和安全风险处置；不得默默沿用过时版本。无法访问上游则标 latest-unverified，禁止宣称已最新；关键安全/接口信息不明时阻断采用，非必需候选可有理由搁置。

每个来源逐项选择：`distill-to-atom`（重新提炼）、`native-tool`（直接调用）、`dependency`（保留成熟实现）、`asset-reference`（必需资产）、`reject`（无益/不兼容/不可验证）。一个来源可拆为多种处理，但只有一份谱系账；蒸馏方法、软件能力、资料资产不是互相替代。不能把真实可用脚本的功能仅浓缩成一句规则后称等价融合。

没有来源能因高星、热门或已有安装自动成为必用项。先判定可解决哪个真实缺口，再判断是全局、领域还是单专家增量；与已有原子重复就合并、改进或取代，不再复制一套。

## 13. 经验积累、女娲治理与持续升级

### 13.1 经验分类

专业（方法/边界）、组织（分工/依赖/交接）、工具（版本/故障/参数）、用户（明确偏好）、项目（术语/事实/验收）分别存放。对话原文、密钥、无关个人信息不作经验库。

用户纠正先生成 correction_event，说明改了什么和适用范围。单次修改不是普遍真理；确认的偏好可在该用户/项目复用，专业事实仍需验证。

原始资料、权威技术规则与学习素材进入6.6知识库，不因“知识也能复用”全部塞进经验池。经验只保存条件化做法及证据引用；知识/经验/任务事实分类校验必须在写入与查询时生效。女娲治理关联和准入，不负责默认全量重读或复制正文。

### 13.2 经验生命周期

`candidate -> scoped -> verified -> reusable -> superseded/revoked/expired`。

记录经验ID、scope、触发条件、解决方法、来源、验证、反例、适用版本、失效条件、授权和TTL。每次任务只检索相关少量经验；优先当前用户要求和事实，经验不能自动改权限或挟持路由。

跨项目晋升不是两库双写：项目候选先发出带幂等键的promotion事件，共享经验库验证授权后接受并返回共享ID，项目仅提交引用；任一步中断保持pending且可恢复。未完成晋升不能被其它项目查询为正式经验。

### 13.3 女娲工作流

新来源/真实失败/用户反馈/官方更新/验证回归 → 登记与去重 → 完整相关材料阅读 → 专业重叠与冲突 → 融合/新增/归档/拒绝提案 → 专业owner复核 → 新写测试及定向回归 → 发布当前单一版本 → 留恢复证据。

普通任务不启动女娲子代理。经验捕获用轻量事件；只有值得治理的事件触发专项工作，不每次后台自我升级。

版本变更不影响已经运行的任务；任务锁定 catalog版本。更新经批准的范围自动执行，涉及新的付费/软件安装/外部数据风险则另取得授权。

### 13.4 留出验证

建立独立设计的测试样例，区分日常回归与未用于调优的留出样例。不能复制此前测试实现，也不能拿WorkBuddy高分当效果证明。留出发现问题后可作为回归用例，但不继续谎称完全未见过。

### 13.5 双通道进化与最大适用传播

```text
新技术/新能力：最新原始来源 -> 差异/许可/安全/执行资产核实
验证经验：真实产物/失败/用户修正 -> 范围/隐私/反例/可复现检查
                       ↓
一份 EvolutionProposal -> 范围判定 -> 原子/专业差异/工具适配候选
 -> 依赖影响闭包 -> 全部受影响消费者重组 -> 对应回归/留出验证
 -> 同一发布门 -> 新相关任务统一启用 -> 观察真实结果/可撤回
```

提案至少写明来源通道、要解决的问题、当前缺陷/成本、具体改进、适用范围、反例、全部消费者、执行资产、权限变化、验收和撤回。不是每条经验都成为全局原子：任务事实留任务；用户偏好留用户/项目；同专业可复用方法进入领域候选；只有跨领域理由和验证足够，才成为全局共同能力。

如 PonyTail 的“最小正确路径”适用于对话、写作、规划、编程、图谱和模板，可统一由全局规则体现；某个Python导入优化只影响相关代码模块，不能替换视频剪辑流程。声音空间运动经验可以用于相应音频/视频任务，但无关文案专家不装载它。

“尽快最大限度生效”指：治理事件到达后立即建立完整影响清单，按风险所需验证，不等待人工逐个改专家；通过后一次发布覆盖所有适用新任务。没有默认后台驻留、定时全网扫描或每轮自我改写；后续主动追踪须用宿主提供的已授权自动化机制。一次用户修正不自动变成普遍真理。

### 13.6 条目delta与知识—经验—能力的有界进化

技术通道：核实最新原始资料/执行资产→KnowledgeRecord或Tool候选→相关方法/原子/专业配方提案。经验通道：真实任务结果/用户修正→最小脱敏事件→scope明确的ExperienceDelta→固定验收→相关消费者更新。两通道在EvolutionProposal汇合，不直接把一次任务日志变成全专家新指令。

delta操作为add/update/merge/retire；带对象类型/ID、expected_revision、scope、证据、原因、失效或撤销条件和幂等键。只更新相关条目，不全量重写知识库、经验池或专家人设；helpful/harmful次数是线索而非正确性证据。知识原文、结构化解释、经验方法及能力实现分别保存权威引用。

来源/工具版本变化沿G-LINEAGE找到相关知识与经验，标needs_revalidation并阻止不适用复用；必要基础事实更新还要核对相关配方/测试。用户偏好变化局限用户scope；组织分工经验影响相关负责人，专业技巧影响相关专家，确有跨域证据才进全局。隐私脱敏、版本锁、完整影响回归及撤回必须保留。

普通反馈只记轻量事件；只有有价值增量、真实失败或明确升级请求才启动女娲专项。离线GEPA/EvoSkill候选研究需已授权预算/环境/动作，不能默认付费试错或修改生产。通过发布门后新任务一次引用新版本，在途保持原锁；跨scope晋升走13.2确认，不把两个库复制成双真源。

进化报告须有：通道、版本新鲜度、改进证据、适用/不适用名单、重组覆盖率、通过/失败测试、权限与资源差异、发布/撤回结果。覆盖率按完整影响闭包计算；未知和未测消费者不能被计为成功。专业owner复核不能仅是候选作者自报通过。

|---|---|---|
| 文本、沟通、代码、规划 | 当前GPT第三方通道，沿14.1三档 | 因Agnes也支持文本就改走Agnes |
| 看图、视觉理解、构图/风格/分镜规划与质检 | 当前GPT视觉通道，实际输入支持需核验 | 把生图服务自动当视觉分析模型；把可看图当可生图 |
| 图像生成/编辑 | 已验证且满足费用约束的既有Agnes服务 | 自动切到付费GPT或Comfy云端 |
| 视频生成 | 任务需要时才选择已验证Agnes视频动作，显式用户要求优先 | 每次图像任务都启用视频；视频权限/额度照搬图像 |
| 可选GPT生图 | 独立provider/action/credential_ref；默认不激活，仅用户明确需要时验证 | 自动创建/索取另一个key，另一个key就宣称具备生图能力 |
| 本地Comfy/时间线/声场加工 | 已验证本地CLI/Skill/API按具体任务执行 | 将本地编辑当生成回退，或依登录状态自动路由收费云端 |

第三方GPT是否能生图不能由提供商身份或模型名字推断。视觉输入、Images生成、Responses的image_generation工具及视频接口分别有能力档案；新增key主要隔离身份/额度，不自动增加端点或模型能力。未证实GPT生图前保持unknown/not-enabled，不因此阻断默认Agnes路线。每种动作的requested_provider/model与实际回执分别记，不能声称同一个接口包办全部能力。

Agnes额度不足/不可用时停在该动作并解释，不静默换收费服务、不轮流尝试其它key；不做收费可用性探针。当前GPT文本/视觉路由不受Agnes故障或备用图像key变更影响。图像、视频、文本、视觉各自健康/费用/授权，不共用一个available布尔值。

每个生成适配器有 capability_profile：provider/model/mode/version、必要参数/参考、duration_control、合法时长/尺寸、声音能力、API证据、probe、expiry、费用与执行授权。

故事时长由内容决定；工具单次时长由能力档案决定；最终成片需实际测量。未知字段、未知时长、未知费用不进入付费批量调用。

### 14.6 REAPER声场集成：项目制作与日常麦克风链路隔离

目标是导入已有对白/SRT、环境、音效与BGM文件，建立轨道/总线、左右移动/空间效果/时间自动化并离线导出混音与分轨；不是替换用户即插即用的USB声卡麦克风、直播或实时监听。ReaScript原生Lua/API为优先候选，命令行承担已验证的启动/项目/渲染动作；SWS/ReaPack或其它插件只在确有必要并核对当前许可/依赖/作用范围后准入，不默认装全套。

硬边界：

- 不修改Windows默认录音/播放/通信设备、驱动、采样率/独占设置、麦克风增益或系统DSP；不安装或启用ReaRoute、虚拟声卡、ASIO4ALL/Voicemeeter等输入路由，不把声场制作连接到当前麦克风。
- 不启用输入录制、录音待命、实时监听或全局机架；工程FX只用于指定文件音轨/总线，不创建全局输入FX或写回用户日常REAPER配置。
- 采用独立制作配置/实例或已验证便携安装候选，媒体/缓存/工程/渲染路径限定任务工作区。具体CLI参数及音频backend先核对安装版本，不照抄未知cfgfile或audio数字值；不运行普通启动来探测，以免读取日常配置/打开设备。
- 优先经验证的不打开实时音频设备的离线渲染路径；预览输出若可能占用当前声卡，只有明确授权且验证安全模式后才用。独立配置并不自动保证设备不被占用，无法证实就停止此路径，不改系统来强行打通。
- 先以已有测试音频验证导入、声场/自动化、工程重开与导出，再核对未改变音频设备/默认端点/用户配置。测试不采集真实麦克风音频，不把设备名清单当作默认端点或无影响的充分证明。

CLI/Skill/插件安装和声场任务是不同授权；未找到常见安装路径不是自动安装许可。任务结束关闭本任务确认归属的实例并释放资源，不关闭用户日常音频应用。不保证未测试环境绝无影响；要求在不能证明隔离时不接管设备，而非边失败边修改麦克风设置。

### 15.3 统一错误类别

`INPUT_MISSING`、`SOURCE_UNREADABLE`、`SOURCE_UNVERIFIED`、`SCHEMA_INVALID`、`SCOPE_DENIED`、`AUTH_REQUIRED`、`MODEL_UNAVAILABLE`、`HOST_CAPABILITY_MISSING`、`DEPENDENCY_NOT_READY`、`WRITE_CONFLICT`、`STALE_REVISION`、`LEASE_EXPIRED`、`BUDGET_EXCEEDED`、`EXECUTION_UNKNOWN`、`ARTIFACT_INVALID`、`VALIDATION_FAILED`、`RELEASE_DRIFT`、`ATOM_CYCLE`、`ATOM_VERSION_CONFLICT`、`COMPOSITION_CONFLICT`、`IMPACT_INCOMPLETE`。

v1.3补充`MODEL_METADATA_MISSING`、`HOST_REQUEST_UNSUPPORTED`、`PROVIDER_REJECTED`、`HOST_QUOTA_EXCEEDED`、`HOST_OBSERVATION_STALE`、`RELEASE_UNVERIFIED`、`INSTALL_RESTORE_CONFLICT`；14.2的分层原因映射到对应错误，认证/瞬时网络/未知提交另按已有分类处理。metadata缺项不自动归MODEL_UNAVAILABLE；配额拒绝先对账排队，释放未证实不归还槽；恢复冲突不全覆盖文件。所有错误带layer、evidence_ref及可安全推进的范围。

## 16. Codex 宿主集成与实际生效

### 16.1 宿主能力表先于集成承诺

P0只读记录版本、平台、实际可用工具、子代理启动/跟进/停止、可见模型/档位、Skill发现、项目规则、配置层级、现有军团入口及相互覆盖。不要读出密钥；不把网页描述当本机验证。

host-capabilities.json使用15.1契约；每个能力项包含configured_value、observed_value、effective_value或unknown、evidence_ref、scope、observed_at和安装版本。记录全局/项目/profile/启动参数的候选覆盖关系、实际受信任与加载证据，无法确认有效层时不强选一个磁盘值。能力变化有失效键，不把P0观察永久缓存到P7。

必查项：原生spawn/follow-up/close schema与释放语义、开放代理额度/占用、逐任务模型/档位挂载点、Skill目录实际投影、9.5各预算语义、CLI绝对路径/版本、插件注册/授权/调用状态。插件enabled=true只证明配置启用；能发现、能授权、能调用、行为通过分别记。agents.max_depth保留为未文档化待验证项，核对安装版schema/无副作用解析或宿主证据后才定性。

同时记录host_class（本地Codex桌面/CLI、托管API、DSH或其它）及证据适用版本。网页API示例、DSH模式选择、MCP扩展规范不能直接证明当前桌面会话有同一字段/上限/自动触发方式；只在本机真实schema与回执范围内承诺。官方URL发生重定向时保存请求/实际文档定位及产品范围，不把不同宿主文档中的配额混为本机effective值。

官方资料表明Codex可以显式/隐式使用Skill，并可在授权的指令场景采用原生子代理。本机是否支持特定配置、模型请求和退出仍须行为探针。版本和入口随时间变化，P0重新核实，不沿用历史缓存结论。

### 16.2 自动组织，不要求用户手选专家

4.0 发布为一个组织入口，description覆盖自然语言任务，声明何时直达、何时按条件委派。目录和专家正文作为冷文件，不把每个叶节点全部安装为全局可发现Skill。

唯一入口明确请求在必要的独立分支使用子代理，满足宿主允许的委派来源；领域入口仍读取其必需指令。自动装载是Skill和宿主机制，不是假设CLI能拦截所有对话。

不引入DSH式模式切换。实际安装前清点3.0现有注册，只替换属于军团且清单明确的入口；其它用户Skill/插件保持不动。是否有更高优先级指令覆盖4.0须以新会话实测。

19.1.1给出具体处置清单，包含developer_instructions、项目/用户AGENTS与覆盖文件、两类Skill目录及插件注册。按语义核对3.0条款，不因版本号不同就全段判冲突；“参谋部非模型工人”“Luna非默认”与本文兼容。未经P7授权保留现有安装态，不以提前删除3.0指令证明4.0可运行。

### 16.3 原生调用适配

prepare产生契约，宿主按当前真实工具schema调用；record引用实际结果，validate核验产物。宿主不支持的字段不硬塞。CLI不能通过写一个receipt.json证明原生代理已经运行。

代理关闭操作以宿主真实可用接口为准；宿主自身对话压缩和主线程热换档不由项目保证。若某关键能力缺失，阻断对应集成门，不另造宿主偷偷绕过。

prepare必须引用新鲜的HostCapabilities和原子槽位预留；record/close更新真实观察而非自报完成。真实quota拒绝、完成未关、关闭请求尚未释放及effective配置变化均有恢复路径。插件调用权限与角色契约分开验证，不通过改插件enabled声称已验证能力。

### 16.4 “已生效”的最低证据

新会话不手动点专家：简单问题走阿极；有界动作正确执行；复杂任务组队并返回真实产物；过期回执/写冲突被拒；已启动代理真实释放；安装前后文件和注册清单可对账。

日志只保留最小行为证据，不保存完整聊天、凭据或无关个人数据。不能用一句“已开启军团”当验收。

### 16.5 用户可见的最小执行摘要

用户无需知道Skill/MCP/专家名，也不必输入军团启动命令。小聊天直接回答，不加军团横幅或人员名单。复杂交付由ExecutionSummary生成简短结果：实际做了什么、验证了什么、仍未完成什么/原因；可附产物和任务记录句柄，详细按需展开。

摘要来自真实任务/宿主/验证记录，不从WorkflowPlan虚构执行。主线程执行专业契约就如实标主线程；只有原生spawn有真实ID才称独立子代理，组织目录角色数不是运行人数。selected/prepared/produced不冒充active/verified；没有执行入口时说明限制，不说“已启用军团所以完成”。不展示隐藏思考链、私密聊天或凭据，不为证明起效每轮输出全图。

阿极的白帽只在影响决定处给人话理由，例如“这个服务的免费额度未证实，所以没有自动转付费”“当前只能做左右移动，不宣称三维声场”；不是全程沉默，也不是机械唱反调。图谱与回执使结果可核查，白帽与PonyTail共同避免无用步骤。G7用无点名专家的简单/复杂自然语言样例证明触发与真实交付，不能拿菜单/CLI demo代替。

## 18. 验收矩阵与质量门

### 18.1 缺陷分级和门禁

P0严重度：越权/数据破坏/秘密泄露/重复收费/伪造完成；立即停止相关路线。P1严重度：必需流程不可用、错误路由、状态错乱、无法恢复、版本/证据失配；发布阻断。P2/P3严重度：有界非关键质量或体验问题；有明确范围、影响和处置才可交付。

这些是缺陷严重度，不与执行阶段P0-P7混淆。报告写 defect_severity 与 phase_id 分开。

### 18.4 性能目标

空闲军团自身常驻进程数为0；清晰任务不全池检索；增加无关专家不增加每次热正文；默认最多2代理并行；目录/状态命令本地样本记录p50/p95、峰值内存、查询范围；无证据不承诺固定降耗百分比。

性能达标不能通过删除必须资料/降低交付质量实现。瓶颈先测量，再优化对应模块，避免先添加新数据库/模型/缓存层。

### 20.1 变更纪律

### E.1 PonyTail 如何全局生效，而不是复制到每个人设

下列为待实现的组合案例；原子ID和版本是设计示例，不证明上游已核实或原子已创建。

| 消费者 | 共用引用 | 专属差异 | 实际验收 |
|---|---|---|---|
| 阿极短答 | bundle/minimum-correct@1.0.0 | 先答结果；问题简单就不建图 | 忠实、必要事实核查、回答简洁 |
| 代码专家 | 同一引用 | 最小正确实现；一行清楚就不多写 | 功能/安全/可维护，不追求晦涩压行 |
| 长文专家 | 同一引用 | 不重复论证；保留用户要求的完整篇幅/结构 | 内容与体裁验收，不把长文强缩成一句 |
| 视频负责人 | 同一引用 | 不需要的节点不启动；必要阶段不能略 | 真实镜头/音轨/导出对账 |
| 图谱查询 | 同一引用的程序约束映射 | 先定位范围，再查必要关系 | 有界且结果完整性说明，无漏验收 |

PonyTail是引用D类等原子的组合包；各原子语义只维护一次，各差异是专业实施方式，不能复制一份改名叫新的PonyTail。以后某组成原子或组合条件升级，所有直接或传递消费者进入影响清单，重新组装/验证；不是只有代码专家收到更新。

最小正确不等于代码高尔夫：清晰三行比危险或难维护的一行更符合此规则。用户明确要详细文档时，少重复而不删必要设计；必要调查/验证不能用“不思考”规避。

### F.19 真正需要统一的L0基础值

| 类型 | 完整语义 | 不能简化成 |
|---|---|---|
| ExactRef | 对象类型/ID、scope、精确revision/schema、内容身份 | 裸ID、latest字符串 |
| EvidenceRef | 来源/观测方式、定位、对象版本、范围/时效、证据等级 | 有个hash就可信 |
| InputBinding | 主/约束输入、正式引用、采用状态、需要的字段 | 一段摘要 |
| DecisionRecord | 决定来源、适用范围、替代/撤销、当前要求版本 | 模型一句“已确认” |
| EffectSpec | 动作、外部影响、读写集合、幂等/查询能力、授权引用 | 一个requires_confirmation布尔值 |
| TimeQuantity | 值、单位、时基、原点、转换/舍入规则 | 一个没有单位的duration |
| Finding | 缺陷原因、对象版本、证据、严重度、owner、受影响范围 | 任意低分或“有问题” |
| MethodApplicability | 前提、适用/排除、参数范围、反例、有效版本 | 只写“擅长” |

这些类型定义一次，通过引用生成各对象schema；不是把每个字段当成独立原子/图节点。基础值升级也要计算schema、数据读写、所有调用实现的影响，按需要迁移并保持在途版本锁。

### F.20 深挖交付与验收边界

P0输出逐候选evidence-ledger；P1确定采用/合并/专业差异/拒绝去向，冻结语义、值类型和组合；P2最小真实执行先用少量基础原子；P3—P5逐域落地共享定义、实现、依赖及进化；P6核对全部实际消费者和表现。不得先生成128个“高质量专家式”文件凑数量。

每项正式采用必须有：atom_ref、source_locator、consumer_refs、semantic_diff、value_types、inputs/outputs、preconditions、failure_kind、positive/negative_fixtures、implementation/evidence_refs、scope/permission、required_dependencies、impact_tests、rollback。组合包另有职责范围和条件图；不能拿L2的测试替代L1独立失败与专业消费者验证。
