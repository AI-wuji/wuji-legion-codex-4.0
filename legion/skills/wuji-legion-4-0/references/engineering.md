# 研发、软件与数据交付

适用：代码修复/开发、项目融合、ComfyUI工作流或插件、前端与交互、安全审查、数据处理与统计分析。清晰的小改动仍直接做，不自动建图。

## 先交付能工作的最小结果
1. 读目标仓库约束、相关实现与已有用例，确定实际输入、允许修改的文件、运行入口和用户要的结果；不先重读整个资料库。
2. 新选型、兼容性或根因不明时，先用已有来源结论；决定性缺口再按研究指引补证。已知错误不要用泛化框架掩盖。
3. 优先修到根因或接通一个真实接口，交付可运行补丁、实际输出或具体审计结论。融合保留Python/TypeScript/Go/C++等原生态，不默认重写为Rust或引入FFI/服务。
4. 只运行与改动风险匹配且已获允许的定向检查；报告实际命令、结果与未测范围，不把mock、schema或编译通过当模型/专业效果。

## 任务内分工
- 一个输出有一个合入owner；窄专家可处理独立模块、样式、分析或证据查核，输入和写集显式交接。
- 同文件或同数据的依赖改动串行合入；复核者给具体缺陷和行/产物位置，不与作者同时覆盖文件。
- 用现有宿主的委派和退出观察；实际并发不可知则保守分批，不新增通用队列、代理协议或第二份任务状态权威。
- 只有任务确需持久化、精确引用、幂等或恢复时，才复用项目已有辅助接口；简单文件改动不承担这些机制的开销。

## 保留专业差异
- ComfyUI：绑定真实workflow、节点/插件版本与输入；注册成功、图能执行和输出质量分别检查。节点名或下载链接不证明已安装/已运行。
- 前端/交互：交付实际页面或组件；按本次设备与核心路径检查响应式、可访问性和可见错误，不拿截图代替交互验证。
- 数据：保留原始样本、清洗规则、单位、分母和缺失值；统计/异常/检索分析按问题选择，相关性不冒充因果，合成数据显式标记。
- 安全：按授权目标做必要检查，优先可复现风险和修复；不扫描无关系统、不读出凭据、不把研究材料当攻击授权。
- 电脑/浏览器工作：先确认当前可见目标和可用原生入口，绑定本次对象与动作；UI、CLI、API入口切换不扩张权限或自证完成。

## 失败与交付
- 外部调用未知是否成功时先查询原调用/目标，不能靠重发有副作用动作“验证”；无进展、越权或429停止该调用，继续不依赖它的工作。
- 验收失败保留错误及输入版本，定点修复；不改断言、删失败证据或改现用配置来制造通过。
- 阿极交付修改路径、真实产物/回读位置、已运行检查和具体未实现边界；审计任务不偷偷变成修改任务。
