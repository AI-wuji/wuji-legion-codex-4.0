# 5.0任务图谱与上下文投影

任务图谱用于长任务、多分支、真实依赖、跨角色交接或上下文压缩时，控制工作范围、执行顺序和上下文载荷。它承接无极军团历史上用图谱表达任务依赖、角色边界和上下文定位的理念；只复用方法，不恢复4.0参谋/主帅必经层级、旧CLI路由或每个角色各建一套重复大图。

## 何时使用

- 简单问答、翻译、短改写、单文件小改等直接完成，不绘制或持久化任务图。
- 出现多个可并行分支、依赖顺序、不同写集/责任人、重要副作用、长时间等待或跨上下文恢复时，建立足以协调工作的轻量DAG。任务过程中复杂度上升时再补图，不预先过度拆解。
- 图谱是任务状态的索引和调度投影，不是计划完成证明、权限授予或新的长期状态库。优先使用当前任务/宿主已有状态与本地真实产物；只有续接确实会丢失时才保存最小摘要。

## 最小节点契约

每个节点只记录会影响执行或续接的字段：

- `id`、短目标、唯一责任人/角色；
- 必要输入引用与写入范围；
- 依赖节点及可并行条件；
- 预期产物和与任务相称的完成判据；
- 状态：`ready`、`active`、`completed`、`failed`、`blocked`、`unknown`；
- 真实证据/回执引用、当前阻塞和唯一下一动作。

只用依赖边表达先后关系；独立且已就绪、权限允许、写集无冲突的节点尽早并发。每个图保持有向无环；图节点不替代授权检查、用户决定或专业验收。

## 上下文控制与失败续办

- 给专家/角色只投影其节点、必要前置结论与输入引用、明确权限/写集、交付物、验收和回交目标；不注入整张项目图、无关历史或其他角色的思考过程。
- 节点完成后回交结果、产物及证据引用，阿极更新图并使下游节点只获取所需输出。面向用户的默认交付仍是结果和必要依据。
- 错误/失败先定位到节点、输入、工具或判据并直接修复；缺依赖就在当前授权范围内安装/配置并确认。修复后只重做受影响节点及其失效后继；未知的外部副作用先查回执/对象状态，避免盲目重复。其余独立分支继续运行。
- 只有真实外部权限、不可替代的用户决定或不可用依赖等无法自行排除的情形才标记`blocked`，记录具体阻塞；报告前推进所有不依赖该阻塞的节点。
- 压缩/交接时只保留图修订、已完成节点证据、待办节点依赖与状态、关键unknown/阻塞和下一动作；能从当前任务上下文恢复时不另写文件。

## 边界

历史`docs/graph-data-model.md`描述的是更完整的逻辑图谱/typed store设计，不代表全部能力都已运行或当前每个任务都应调用它。5.0日常任务可在对话上下文中维护轻量图；只有宿主实际提供并且任务需要时才用持久图存储。不得为此另造常驻调度平台、第二事实库或固定角色层级。
